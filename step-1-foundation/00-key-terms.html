00 · 先认识这几个词

后面 9 页会反复出现这些词。这一页把它们讲清楚：每个词一块，先说是啥、再说什么时候用得上、最后给个类比。 不用背，看不懂的时候回来查。

第一遍（5 分钟）只看每块的第一句话，跳过类比。先有个大概轮廓。
第二遍（20 分钟）读完整块，包括类比和例子。
第三遍（5 分钟）做页尾回忆卡，自己讲一遍。

第一组 · 认识大模型

这组回答："模型到底是什么、它做不到什么"。搞懂它的三个限制（不知道你的资料、记不住新东西、会编），后面为什么要 RAG、为什么要 Agent 就顺理成章了。6 个词

大模型 LLM ★ 高频

是什么
能理解和生成文字的 AI，比如 Claude、GPT、Gemini。你平时用的"AI 助手"，背后就是它。
它的限制
它只"读过"训练时喂给它的资料。没喂过的（你们公司的内部文档）、太新的（昨天发生的事），它都不知道。而且它不会主动承认自己不知道。
类比

一个读过很多书、但从没进过你们公司、也不知道昨天新闻的人。他很会表达，但你问他没读过的事，他会顺口猜一个。

Prompt 提示词 ★ 高频

是什么
你发给大模型的那段文字。问题、指令、要求、示例，全都算。
什么时候用得上
每一次调用模型都在用它。同一个模型，提示词写得好不好，效果差很多。
类比

给上面那个人写的便条。"帮我看看这个"和"按这三条要求改这段代码，别动其他逻辑"，他给你的结果完全是两回事。

上下文 Context ★ 高频

是什么
模型这一次能看到的全部文字：你的问题 + 之前聊过的内容 + 检索到的资料 + 工具返回的结果，全都算在内。
为什么重要
没放进去的东西，它一律看不见、也想不起来。所以"给它什么资料"直接决定了它答得好不好——这是整份材料里最重要的一条认知。
类比

摊在他面前的桌面。你只能通过桌面上摆的东西影响他——没摆上去的，对他等于不存在。

上下文窗口 Context Window

是什么
这张桌面最多能摊多少东西，是有上限的（不同模型上限不同）。
为什么重要
塞满了就得清理掉一些。这就是后面 Agent 为什么必须做"上下文管理"的根本原因。
类比

桌子大小是固定的。资料堆到放不下时，你要么先收走一些，要么就没法再摊新的上去。

token

是什么
模型计算长度和费用的单位，大约等于一个词或半个汉字。
为什么重要
上下文越长 = token 越多 = 越贵、越慢。所以"能少塞就少塞"不是在抠门，是在省钱。
类比

打车的计价里程。你塞进去的每一段文字都在计费。

幻觉 Hallucination ★ 高频

是什么
模型不知道答案时，不承认不知道，而是编一个听起来很合理的内容。
为什么重要
这是 AI 应用里最危险的失败模式——它不会说"我不清楚"，而是自信地给你一个错的答案，你很难察觉。
怎么治
给它资料照着答（就是下面的 RAG），并且要求它标注出处。
类比

一个特别好面子的人。你问他不知道的事，他不说"我不知道"，而是顺口编一个，语气还特别肯定。

第二组 · 让它知道你们的资料

这组解决第一个限制：模型不知道你们公司的内部资料。核心思路一句话——提问时先把相关资料找出来，塞进它的上下文。5 个词

向量 Embedding / 嵌入 ★ 高频

是什么
把一段文字变成一串数字（比如 1024 个小数）。关键性质：意思相近的文字，算出来的数字也相近。
为什么重要
这样一来，"找相似内容"就变成了"算数字距离"，机器才能一秒从上百万段里找出相关的那几段。
类比

给每句话在一张超大的地图上标一个坐标。"报销怎么弄"和"差旅费用规定"会被标在很近的位置；"今天天气不错"则离得很远。找相关内容 = 找附近的点。

向量库

是什么
专门存这些"坐标"、并能飞快找出离得最近的几个的数据库。
为什么重要
数据量上百万时，一个个比对太慢，靠它来加速。
类比

一张能瞬间回答"离我最近的 10 家店是哪几家"的地图。

切分 chunk

是什么
把长文档切成一段一段的小块，每块单独算向量。
为什么重要
粒度要合适：切太大，一块里什么都讲一点、什么都没讲清，算出来的向量也"糊"；切太小，句子被拦腰截断，意思不完整。
类比

把一本厚书拆成一张张卡片，以后按需抽卡片。检验标准很简单：随便抽一张出来单独读，能不能读懂？

召回与精排 Retrieval / Rerank ★ 高频

是什么
召回＝先从海量内容里快速捞出几十条"可能相关"的候选；精排＝再从这几十条里精挑出最相关的三五条。
为什么分两步
先用快的方法保证"不漏"，再用慢但准的方法保证"精准"。一步到位做不到——要么太慢，要么不准。
类比

初筛。先按关键词筛出一批候选（求快求全），再逐份细看挑出最合适的（求准）。

RAG 检索增强生成 ★ 高频

是什么
先去资料库里找出相关段落，再把这些段落塞给模型，让它照着资料回答。
解决什么
同时治两个毛病：模型不知道你的私有资料、以及它会编。答案是"有依据"的，还能标出出处。
类比

开卷考试。闭卷时它只能凭记忆答（会编）；开卷时先把资料摊在桌上，它照着答，还能标出"这句出自第 3 页"。

第三组 · 让它会做事

这组解决另一个限制：模型只会说话，不会动手。办法是给它"工具"（能真的去搜、去算），再给它一个"循环"（做完看结果，不够再来一轮）。5 个词

工具调用 Function Call / Tool Use ★ 高频

是什么
模型输出一段结构化指令，说"我要查天气，城市=北京"；然后由程序真的去查，再把结果塞回给它。
最容易误解的一点
模型自己不执行任何操作，它只会"说要干什么"。真正跑腿的是围绕它的程序——所以"给它配了哪些工具"，决定了它能做哪些事。
类比

模型是个只会动嘴的参谋，不会动手。他说"派个人去查一下库存"，真正跑腿的是别人。

Agent 智能体 ★ 高频

是什么
大模型 + 工具 + 循环。它拿到一个目标后，自己判断下一步做什么，做完看结果，不够就再来一轮。
和 RAG 的区别
RAG 基本是"提问 → 检索 → 回答"一条直线；Agent 多了一个循环，能根据中间结果调整下一步——比如发现搜到的东西不行，它会换个词再搜。
类比

从"问答机"变成"实习生"。你问他问题，他只能回答；你让他做事，他会自己安排：先查资料、发现不够再查一轮、然后动笔写。

多 Agent Multi-Agent

是什么
把一个大任务拆给几个各有分工的 Agent，比如一个负责查资料、一个负责写、一个负责审。
好处与代价
好处是每个人只管自己那摊，思路不会被别人的过程带乱；代价是要互相沟通，信息在传递过程中会丢。
类比

小组作业分工。分工明确效率高，但交接不清楚就容易互相甩锅。

MCP

是什么
一套开放协议，把各种工具和数据源标准化，让任何支持它的 AI 客户端都能直接接上。
解决什么
以前每个工具都要为每个 AI 单独适配一遍，工作量是"工具数 × 模型数"；有了统一接口就变成"工具数 + 模型数"。
类比

USB-C 接口。以前每台设备都要配专属的线，现在一根线通用。

Skill 技能

是什么
一份打包好的"做事方法"：提示词 + 脚本 + 参考资料，需要时才加载。
解决什么
它教的是"这类活儿该按什么流程干"，而不只是"有哪些工具能用"。工具是手脚，Skill 是操作手册。
类比

老员工留下的《报销怎么走》《客户投诉怎么处理》。新人不用重新摸索，照着做就行。

第四组 · 工程实现时会碰到的词

这组是横跨上三层的实现细节，第一遍不用深究，知道有这么回事即可，后面各页会展开。4 个词

流式输出 SSE / WebSocket

是什么
模型生成到一半，就把已经写好的部分先发给你，而不是等全部写完再一次性返回。
为什么重要
用户体感快很多——虽然总时长其实一样。你看到 AI 回答"一个字一个字往外蹦"，就是它。
类比

对方边想边说，而不是憋完一大段再开口。

微调 Fine-tune

是什么
拿你们自己的数据再训练一下模型，改变它的说话方式或擅长的领域。
为什么重要
它适合教"怎么说"（输出格式、语气、术语习惯），不适合教"说什么"——知识更新应该用 RAG，因为微调一次很贵、还没法随时更新。
类比

送员工去专项培训。能改他的表达习惯，但改不了"他不知道公司昨天发了什么通知"这件事。

框架 LangChain 等

是什么
别人写好的工具箱，帮你把"调模型、连数据库、串流程"这些重复劳动封装起来。
要注意的
省事，但出问题时你得先搞懂它的结构才能修；而且版本更新快，容易踩不兼容。
类比

宜家的半成品家具。装起来快，但坏了要修的时候，你得先研究它怎么拼的。

离线与在线 两条链路

是什么
离线＝提前把文档处理好存进库（用户看不到这个过程）；在线＝用户提问时，现场检索和回答。
为什么这么分
两边的优化目标完全不同：离线可以慢慢做、做一次用很久；在线必须快，用户就在旁边等着。
类比

备菜和炒菜。备菜可以提前一上午慢慢切，炒菜必须几分钟内出锅。

回忆卡 · 合上材料，用大白话讲一遍

为什么光有大模型还不够？RAG 解决了什么问题？Agent 又比 RAG 多了什么？

讲完了，展开对照

光有大模型不够，因为它只知道训练时见过的东西——不知道你们公司的内部资料，也不知道最新消息；而且不知道的时候它会编（幻觉）。

RAG 解决"知道"的问题：提问时先去知识库里捞出相关资料，放进上下文让它照着答。这样既能用上私有资料，答案也有出处、不容易乱编。

Agent 多了"会做"：RAG 基本是"提问 → 检索 → 回答"一条直线；Agent 多了工具（能真的去搜网页、跑代码）和循环（做完一步看结果，不够就调整下一轮），所以能完成"调研并写报告"这种没法提前写死步骤的任务。

这些词会在哪里出现

01~05 讲第二组（RAG 这条线）；06~08 讲第三组（Agent 这条线）；09 是自查。第一组和第四组的词两边都会用到。

读的时候遇到不懂的词，回来查；还是不懂，就先跳过往下读——很多概念看到后面自然就通了。

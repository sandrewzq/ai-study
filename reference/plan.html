242 道题按知识域分成 A~J 十个域，排成步骤 0~5 的学习顺序。下面的目录可直接跳到任意章节。

读正文前先知道这个

计划里把 242 题分成 A~J 十个知识域（按学习顺序编号）：A = LLM 与 RAG、B = Agent 与多智能体、C = 上下文治理与流式通信、D = 后端与数据、E = 前端、F = 量化与成本、G = 项目叙事、H = AI 工作流、I = 工程化、J = 软性与职业。

0. 这份文档怎么用

三件事，各用一遍：

  1. 体检：把题目索引里的清单从头扫一遍，每题打一个标记 —— - [x] 表示「能讲 3 分钟」，- [ ] 表示「答不利索」。只学没打勾的。
  2. 突破：按第 1 节的 A→J 顺序学，不要按公司顺序、也不要按题量顺序。
  3. 模拟：开始之前用它抽题。随机从 5 个不同域各抽 1 题，连问 40 分钟，模拟真实节奏。

原文件是实际提问顺序（按公司），这份文档是学习顺序（按知识域 + 依赖关系）。两份配合用。

为什么是这个顺序

不是按题量，也不是按重要性，而是按依赖关系：前面学的东西是后面东西的前提。

  1. A + B 打地基（步骤 1）：这两个是方向门槛，也是你做项目时的「图纸」。不先建立认知就直接上手做项目，只能照着教程抄，对方一追问就穿帮。
  2. C + D 做系统（步骤 2）：这两域的题几乎全是「你有没有真做过」，纸上准备不出来，只能在项目里练。它们是把前两步变成能跑的系统的能力。
  3. E 保分（步骤 3）：这是你的存量优势区，也是题量最大的一域，但恰恰最不需要提前学 —— 集中突击几天刷完基础题即可，省下的精力给做项目。
  4. F 量化（步骤 3）：数字必须是项目真跑出来的，必须排在项目之后，提前准备只能编，编了会连环翻车。
  5. G 讲故事（步骤 4）：项目做完才有素材。这也是为什么它虽然题量第三，却排在很后面。
  6. J 冲刺（步骤 5）：写稿背熟就行，学早了会忘，放最后收益最高。

两域不占步骤：H（AI 工作流与个人效能）全程并行，日常用 AI 时顺手积累；I（工程化）按目标方向取舍。

注意：以上是投入顺序，不是「做完一个再做下一个」。C、D 两域与步骤 2 的项目是交织进行的。

这份计划不排时间表，只排顺序。每个步骤在第 6 节都给了明确的「完成标志」，达标了就进下一步，没达标就继续 —— 进度取决于你每天能投入多少，跟日历无关。

两个关键结论

最关键的一条结论：纯 AI 知识（A + B）只有 45 题，占 19%。 一半以上的题是「工程基本功（D / E / I）+ 项目叙事与量化（F / G）」。

所以正确的准备姿势不是「去学 Agent 技术」，而是：用一个真实的 AI 项目，把工程基本功串起来讲。 只会背 RAG 流程的人，会在 D、E、F、G 四域上大面积失分。

另一个信号是重复率：SSE/WebSocket 重复出现 5 次，RAG 检索链重复出现 7 次，Vue 响应式重复出现 3 次，成本/用量类数字题几乎家家都问。这些重复出现的就是必考项（见第 2 节）。

4. 高频追问链（真正的分差在这里）

对方不会只问一层。下面 6 条链是最高频的追问路径，每条都标了它属于哪个学习步骤。

怎么用：每题先自己讲一遍，讲完再对照「要点」补漏。要点不是名词清单，是一句「按什么顺序、讲哪几件事」的话——照着它就能起头，细节和数字再回材料页。每段末尾的「配套题」点进去，就是讲这道题的那份材料，要点就是那份材料里答法的压缩版。

4.1 RAG 检索链

A 域 · 步骤 1 打地基　·　JR / HQ / PY / YF 四家都在追
  1. 主问题RAG 整体流程是什么？ 要点分两条链说，不要揉成一条：离线（解析 → 切分 → 向量化 → 入库，原文和元数据同时进 ES）；在线（查询改写 → 混合召回 → RRF 融合 → 权限与生效期过滤 → 精排 → 组装提示词生成，并要求标注出处）。收尾补一句工程细节：每条数据都要带元数据（来源、版本、生效时间、权限），否则后面做过滤、做引用、做权限控制都要返工。
  2. 追问怎么加速检索？ 要点别堆手段，先分诊瓶颈：查询处理慢就加缓存，召回慢就调 efSearch 或加元数据预过滤，精排慢就缩候选集，生成慢就上流式先把首字吐出来。
  3. 追问召回不准怎么办？ 要点三步：查询改写 → 混合检索（ES 关键词 + 向量语义，RRF 融合）→ 交叉编码器精排。
  4. 追问已经分组、排序、去重了，为什么还要 rerank？ 要点粗排是双塔、比的是语义相似，而相似不等于能回答问题；精排用交叉编码器把问题和文档拼在一起逐词对齐，才算得准。
  5. 追问加了 rerank 延迟上升怎么办？ 要点三招：候选从 100 缩到 30、高频问题走结果缓存、精排本身做批处理。
  6. 追问怎么证明改完真的变好了？ 要点先有评测集；看两个命中率——召回 50 条的、精排 Top 5 的；政策这类答错要出事的场景再加人工抽检。

配套题：JR-5 JR-6 JR-10 HQ-27 HQ-29 HQ-30 HQ-31 PY-5 YF-6 YF-7

4.2 多 Agent 链

B 域 · 步骤 1 打地基　·　ML 连问 6 题，本质是一条链
  1. 主问题什么是多 Agent？ 要点先纠一个常见误解：多 Agent 的核心不是「分工」，是「把上下文隔离开」——每个 Agent 有独立角色和独立上下文。三个症状各对一个根因：错误假设留在上下文里把人带偏、自己评审自己永远说「还不错」、发散和收敛混在一个提示词里自己跟自己打架。并行和交叉验证是拆完顺带拿到的，不是目的。
  2. 追问为什么需要多 Agent？ 要点两个根因：上下文污染、角色冲突；并行和交叉验证是顺带拿到的。
  3. 追问单 Agent 也能分配多个职能，为什么还要拆？ 要点职能分配了，上下文还是同一份——拆的本质是给每个角色一份干净的上下文。
  4. 追问什么场景下才值得拆？ 要点拆有代价：通信成本、状态一致性、排查难度；只有子任务需要不同上下文、或者能并行时才拆。
  5. 追问多 Agent 怎么路由？ 要点静态图 vs 动态路由；我们的做法是主 Agent 只负责分派和汇总，各角色配独立工具集（HQ-26）。
  6. 追问怎么防止多个 Agent 互相「踢皮球」或死循环？ 要点先划责任边界再定终止条件：谁负责、要交付什么、几轮之内必须收敛。

配套题：ML-5~ML-10 HQ-26 YU-19

4.3 流式通信链

C 域 · 步骤 2 做系统　·　5 家都问，细节题最杀人
  1. 主问题SSE 和 WebSocket 有什么区别？各自适用场景？ 要点一句话先给区别：最本质的是方向——SSE 服务器单向推，WebSocket 握手之后是双向的。落到选型：只是服务器把数据推给前端看（推 token、推进度）用 SSE；要频繁双向交互或传二进制才上 WebSocket。
  2. 追问你们都用了哪个？为什么？ 要点只要单向推 token 就 SSE：少写一套重连逻辑、天然兼容网关；要双向交互或传二进制才上 WebSocket。
  3. 追问WebSocket 有没有做心跳保活？断了怎么重连？ 要点心跳：30 秒 ping/pong，连续 2~3 次没回就判死。重连：指数退避 + 随机抖动（不加抖动，所有客户端会在同一刻一起重连把服务端打垮），并且只对网络错误重连。
  4. 追问连不上怎么兜底？会降级成 HTTP 轮询吗？ 要点会：降级轮询，频率动态放慢（有数据 2~3 秒、没数据逐步到 10 秒、切后台暂停）；再不行就给明确提示和一个「重试」按钮。
  5. 追问SSE 断线续传怎么做？ 要点把「连接」和「任务」解耦：任务在服务端独立存储，每条输出带递增 seq，重连时用 Last-Event-ID 上报，服务端把 seq 之后的内容补发。
  6. 追问后端流式推、前端边收边渲染，怎么做状态同步？ 要点一句话原则：让用户随时知道系统处于什么状态，并且永远留一个出口。重连用横幅不弹窗，可能过期的数据加时间戳或置灰。

配套题：FN-6 YC-10 HQ-18~HQ-22 YF-20 SH-10~SH-21

4.4 上下文治理链

C 域 · 步骤 2 做系统　·　claude code 相关题都挂在这条链上
  1. 主问题你的上下文压缩策略是什么？ 要点先给原则再给方法：核心原则是「最好的压缩是不需要压缩」——优先从源头上不让脏东西进上下文。然后按优先级报四层：① 隔离（脏活交子 Agent，主线只拿结论）；② 外部化（大结果落盘，上下文只留路径和摘要）；③ 摘要（长对话滚动总结，关键约束用结构化对象存）；④ 截断（最后手段）。
  2. 追问压缩后质量下降怎么办？ 要点三件事一起做：关键信息用结构化字段存、不靠模型摘要；原始内容落盘可回溯；压缩用更强的模型并做一次校验。
  3. 追问那怎么避免上下文被污染？ 要点主线程只留结论，装环境、跑测试这类脏活丢给子 Agent——最好的压缩是不需要压缩。
  4. 追问claude code 的上下文治理怎么做的？ 要点三层：脏活丢给 sub-agent 做隔离、长对话滚动摘要、工具返回的大结果只留路径和摘要不回灌全文。
  5. 追问claude code 的核心循环是什么？ 要点读 → 想 → 调工具 → 回灌；关键是「下一步做什么」由模型看着当前情况现判，没有任何一步是提前写死的。
  6. 追问多轮循环怎么防止死循环和 token 爆炸？ 要点两件事分开管：循环靠终止条件和轮次上限兜底；token 靠工具结果落盘、滚动摘要和结构化字段压。

4.5 异步任务与可靠性链

D 域 · 步骤 2 做系统　·　HQ / PY 两家的深水区
  1. 主问题视频解析 / Embedding 这种长任务为什么用队列？ 要点别罗列技术名词，按「入队 → 消费 → 完成」三段讲：入队立刻返回「已受理」，不让用户等；消费端匀速拉取，把瞬时压力摊平（削峰）；完成情况落成数据，进程崩了也能重投、重试、续跑。一句话收尾：队列换来的不是性能，是「不丢、可重试、可削峰」。
  2. 追问进程崩溃 / K8S 重启后任务会不会丢？ 要点三个风险点分别堵：入队前先写一条 pending 任务记录（投递失败还能扫出来补投）、消费中手动 ack（不 ack 就重投）、确认前靠业务幂等兜底。
  3. 追问怎么保证不丢 + 一致性？ 要点先认一条认知：队列保证的是至少一次投递，不是恰好一次——所以重复是必然的，目标不是「防止重复」，而是「让重复没有副作用」。
  4. 追问重试导致重复执行、重复调用大模型怎么办？ 要点幂等键建唯一索引，执行前先查、执行后落库；AI 场景里重复不只是数据问题，是直接烧钱。
  5. 追问任务中途中断怎么断点续跑？ 要点进度落表，重跑时按已完成的批次跳过——代价只落在没做完的那一段，而不是整个任务从头再来。
  6. 追问前端怎么感知任务中断 / 运行状态？ 要点别只依赖长连接：进页面先调一次任务状态接口拿当前状态和已有内容，再用连接接后续增量——长连接只能收到「连接之后」的变化。

配套题：HQ-14~HQ-18 PY-20~PY-22

4.6 成本优化链

F 域 · 步骤 3 量化　·　ML 连问 6 题
  1. 主问题你有没有考虑过怎么节约 AI 成本？ 要点这题考的是结构不是数字，按四步走：先表态「算过账」→ 拆成本构成（模型调用占大头，向量库和服务器占小头）→ 按性价比报手段（缓存 > 减少输入 > 模型分级，外加去重）→ 最后给降幅和统计口径，并主动补一句「没牺牲效果」。别一上来就报一个百分比。
  2. 追问做了哪些优化方案？ 要点按性价比排：第一是缓存，相同问题不重复调用，省得最多也最简单；第二是减输入（精排后只留最相关的几段、历史对话做摘要）；第三才是模型分级。
  3. 追问为什么这样做有效？ 要点先拆成本构成再动手：模型调用占大头，而其中输入 token 比输出更值钱——这是 RAG 场景的特点，因为要把检索到的资料塞进去。
  4. 追问最终降了多少？ 要点三个数一起给：降的百分比、省下的绝对金额、以及统计口径（按 token 还是按调用次数），缺一个都会被追着问。
  5. 追问降本有没有牺牲效果？怎么监控？ 要点先做不影响效果的（缓存、去重、精简输入），再做要权衡的（模型分级），而且分级必须配兜底和效果监控——分错模型省下的钱可能不够赔体验。

配套题：ML-11~ML-16 HJ-1 HQ-16

5. 答题标准：60 / 80 / 100 分

每道题都按三档准备，对方一个追问就能分辨你在哪一档：

档位表现例子（以「为什么需要多 Agent」为例）
60 分说得出定义和结论「因为要分工，每个 Agent 负责一个职能。」
80 分绑定自己项目 + 数字 + 坑「我们拆了检索、代码、评审三个 Agent，拆之前单 Agent 上下文里混着调研笔记和历史失败方案，越到后面 idea 越飘；拆开后每个 Agent 上下文干净，评审结论一致性明显提升。」
100 分讲清 trade-off 与边界「但拆不是免费的：多 Agent 有通信成本和状态一致性成本，任务拆得太细反而会因为信息丢失而变差。我的判断标准是——只有当子任务需要不同的上下文或可以并行时才拆，纯粹为了『看起来更专业』而拆是负收益。」

口述统一用五段式，能套住 80% 的题：

结论 → 我项目里怎么做的 → 数字 → 踩过的坑 → 权衡与边界

7. 优先级取舍与避坑

按目标方向取舍：

目标必练可以放弃
AI 应用 / Agent 开发（主流）A B C F G + D 的核心（事务/索引/队列）SH 的前端动画细节（SH-1~SH-9）
偏全栈 + AI上面全部 + E—
明确投 HQ 这类 NestJS 岗加练 HQ-1~HQ-17（TypeORM/Bull/Nest 全套）前端动画
明确投 TK 这类企微生态岗加练 TK-1~TK-7（企微登录/域名/埋点/ID 同步）多 Agent 深挖

避坑清单：

  1. 不要按公司顺序学。那是实际提问顺序，不是学习顺序。
  2. 不要按题量顺序学。E 域题量最大但最该晚点碰，F 域题量最小却必须等项目跑完 —— 决定顺序的是依赖关系，不是题量。
  3. 不要背概念不准备例子。B 域的题全部会落到「你的项目里怎么用的」。
  4. 不要逐行读 claude code 源码。对方问的是「上下文治理思路」和「核心循环」，读官方工程博客 + 自己实现一遍 agent loop 就够（JR-13~JR-15 KJ-1）。
  5. 不要回避数字题。这是唯一无法靠话术绕过的题型（第 3 节）。
  6. 不要忽视 D 域。它题量第二，且 AI 应用的深度恰恰体现在这里。
  7. 不要只练不录音。口述和默想的差距，比你想象的大得多。

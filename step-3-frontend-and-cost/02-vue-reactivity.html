02 · Vue 响应式原理

「Vue 2 和 Vue 3 响应式有什么区别」是前端岗重复率最高的题之一。 这一页只讲一件事：两种实现到底差在哪，以及为什么 Vue 3 要换掉它。

0. 先看一个场景

你在维护一个老项目，Vue 2 写的。某天加了个功能：给列表里每一项补一个「已读」字段。

代码是这么写的：

看起来没问题

this.list[0].read = true;

数据确实改了，但页面上那个红点没消失。控制台打印 this.list[0]，明明 read 已经是 true。

这就是 Vue 2 最有名的一个坑。它的根源不在你的代码写错了，而在框架根本没"看见"这次修改——Vue 2 的响应式是在对象初始化时逐个属性装监听器，事后新增的属性不在监听名单里。

Vue 3 换了个做法，这个坑就消失了。这一页就是讲这两种做法。

主图 · 一句话概括两代的差别

Vue 2 是在每个属性上装监听器；Vue 3 是给整个对象套一层代理

这张图在说什么：Vue 2 的做法像给每个房间单独装一个门铃——装的时候得挨个房间去装，而且事后新隔出来的房间不会有门铃。Vue 3 的做法像在整栋楼门口装一个门卫——不管里面怎么改，进出都得经过他。

这就是为什么 Vue 2 里「新增属性不响应」，而 Vue 3 里同样的代码直接就生效了。

颜色含义： Vue 2 的做法 Vue 3 的做法 两者差异带来的结果 限制 / 不支持的场景

1. 先搞懂「劫持」这两个字

「劫持」听着吓人，其实就一句话：把对象的属性改造成一对读写函数，读的时候记一笔、写的时候通知一声。

JS 里做这件事有两种工具，这就是 Vue 2 和 Vue 3 的分水岭：

工具怎么用它的局限
Object.defineProperty
（Vue 2）		 针对一个对象的某一个属性，重新定义它的 getter 和 setter。要覆盖所有属性，就得循环遍历、逐个定义。 只能管定义时已经存在的属性。事后新增的、删掉的、以及数组按下标赋值，它都收不到通知。
Proxy
（Vue 3）		 针对整个对象建一个代理。之后所有读写都先经过代理，它可以在那里统一拦截十几种操作。 它是一个语言层面的新东西，旧浏览器没有。这是 Vue 3 放弃兼容老浏览器的原因。
一个类比

Object.defineProperty 像是给一本书的每一页都贴一张便利贴——贴的时候得逐页贴，而且你后来撕掉一页、或者往书里塞一页新的，新页上就没有便利贴。

Proxy 像是在书的封面上装了一个电子标签——不管谁翻到哪、加了页还是撕了页，都得先过这道标签。

所以两者的核心区别不是"谁更快"，而是"能不能覆盖那些结构性的变化"。Vue 2 的那些坑，全是这个局限带来的。

2. Vue 2 是怎么做的

Vue 2 初始化数据时会做三件事：

① 递归遍历对象
从根对象开始，一层层往下走。遇到嵌套对象就继续递归——所以数据层级越深，初始化越慢。
→
② 给每个属性定义 get/set
读取时（get）把"谁用到了我"记下来，这叫依赖收集；写入时（set）通知这些依赖"我变了"。
→
③ 数组单独处理
数组没法用上面这套（数组的下标不算"属性"），所以 Vue 2 换了个办法：把数组的 7 个常用方法改掉，在调用前后补上通知逻辑。

第 ③ 步是 Vue 2 最特殊的地方，也是HQ-32 那道题问的。改掉的是这 7 个方法：

被重写的 7 个数组方法

push　pop　shift　unshift　splice　sort　reverse

原理是：先照常调用原方法，再手动告诉框架"这个数组变了"。因为改动被"包"在方法里，所以能被感知到。

由此就推出两个它管不到的场景（HQ-33）：

写法能响应吗为什么
list[0] = 'x'不能按下标赋值不经过那 7 个方法，等于绕开了所有监听。
list.length = 0不能改长度属性同样不经过方法。这也是"清空数组却没更新视图"的常见原因。
obj.newKey = 1不能新增属性时对象已经遍历完了，这个 key 从来没被定义过 get/set。
Vue 2 里的标准解法

用框架给的专用 API：this.$set(obj, 'newKey', 1)，数组则改用 splice：this.$set(list, 0, 'x') 或 list.splice(0, 1, 'x')。

这个 API 内部做的事情就是：先手动把新属性也定义上 get/set，再赋值，然后通知更新。等于手工补上缺失的那一步。

3. Vue 3 换了做法，顺带解决了什么

Vue 3 用 Proxy 包住整个对象。这一换，Vue 2 那三个坑同时消失——因为拦截发生在"整个对象"这一层，新增、删除、下标赋值全都会经过它。

但好处不止这些（SH-36、HQ-34 问的就是这个）：

维度Vue 2Vue 3
能不能拦截 读写属性两种 读写属性、增删属性、in 判断、删除操作等十几种
什么时候递归 初始化时全部递归一遍，用不到的数据也要处理 用到哪一层才代理哪一层（惰性），大对象初始化更快
是否改动原对象 会：原对象的属性被替换成了 get/set 不会：原对象保持原样，代理是"外面那一层"
代价 兼容性可以做到很老 老浏览器不支持 Proxy，且这个没法用语法糖补上
这题的加分点

把"好处"讲成一条因果链，而不是罗列特性：

「Proxy 能拦截整个对象的所有操作 → 所以新增/删除属性、数组下标赋值都能响应 → 那些 $set 的历史包袱就没了；而且它能在真正访问到某一层时才去代理 → 大对象不用一次性递归到底 → 初始化更快。」

最后补一句代价：「代价是放弃了 IE，因为 Proxy 无法用语法糖降级实现。」

4. 两个必然被追问的点

讲完原理，对方通常往两个方向追：内部是怎么存依赖的（问 WeakMap），以及"那是不是 Proxy 就一定更快"。这两个点答好了，这一组题基本就稳了。

追问一：「Vue 3 里的 WeakMap 是干嘛的？」（HQ-35）

这是这一组里最能看出你有没有真的读过实现的一题。答案不复杂，关键是要说清"为什么非要用 WeakMap"。

它解决的问题：框架需要维护一张表——"哪个对象的哪个属性，被哪些副作用依赖着"。这张表的键是对象。

为什么不用普通 Map：普通 Map 会强引用它的键。也就是说，一个组件已经销毁、对象理论上该被回收了，但因为它还躺在这张表里当键，垃圾回收就收不走它——内存泄漏。

WeakMap 的区别：它对键是弱引用——不影响垃圾回收。对象没别的引用了，就可以被回收，表里对应的那条也会自动消失。框架不需要自己管理清理逻辑，这也是个性能账。

另外它还有第二个用途：缓存已经创建过的代理对象。同一个对象重复取代理时要返回同一个，否则会出现"同一个数据有好几个代理"，更新就乱了。

追问二：「那 Proxy 是不是一定比 defineProperty 快？」

不是，这是个常见误解。要分开看：

  • 初始化：Vue 3 通常更快，因为惰性代理不用一次性递归到底。
  • 单次读写：Proxy 是在语言层面加了拦截，理论上比原生的属性访问多一层开销，所以在极端密集的读写场景下不一定更快。

所以准确的说法是：Vue 3 更快，主要不是因为 Proxy 本身快，而是因为它在编译阶段就把大量比对工作省掉了——响应式只是其中一环。编译时具体做了什么，见下一份。

这一段就是答案：按顺序把这几件事讲一遍，讲不下去的地方回上面正文补。再往下的「回忆卡」是自测（先合上材料讲，再展开对照），「动手清单」是怎么落到自己项目里。

「Vue 2 和 Vue 3 响应式的区别 / 原理」

【结论】核心区别一句话：Vue 2 是给每个属性装监听器，Vue 3 是给整个对象套一层代理。

【Vue 2】用 Object.defineProperty。初始化时递归遍历所有属性，逐个重新定义 getter 和 setter——读的时候收集依赖，写的时候通知更新。数组特殊，因为它没法按属性处理，所以 Vue 2重写了 7 个数组方法（push、pop、shift、unshift、splice、sort、reverse），在方法里补上通知。

【局限】这套做法有三个覆盖不到的地方：新增属性、删除属性、按下标改数组。因为监听器是在初始化那一刻装好的，之后的结构变化它看不到。所以 Vue 2 提供了 $set 这个补救 API。

【Vue 3】用 Proxy。它拦的是整个对象，读写、增删、下标全都经过它，三个坑同时消失；而且它是用到了才代理下一层，不用初始化时递归到底。内部用 WeakMap 存"对象 → 依赖"的映射，弱引用不影响垃圾回收。

【权衡】代价是 Proxy 在旧浏览器上不存在，且没法用语法糖降级——这就是 Vue 3 不支持 IE 的根本原因。另外要说清：Vue 3 更快主要不是 Proxy 的功劳，而是编译时做了静态提升和补丁标记。

回忆卡 1 · 合上材料，用自己的话讲一遍

为什么 Vue 2 里 this.list[0] = 'x' 改了视图不更新？Vue 3 为什么没这个问题？

讲完了，展开对照

Vue 2：响应式是在初始化时逐个属性装 get/set 的。数组的下标不算"属性"，走不了这条路，所以 Vue 2 改成重写 7 个数组方法来补——但按下标直接赋值不经过任何方法，等于绕开了全部监听。

Vue 3：Proxy 拦的是整个对象，按下标赋值也会经过代理的 set 拦截，所以天然能感知。同理，新增和删除属性也一并解决了。

一句话对比：Vue 2 的监听是"装在属性上的"，所以新增的结构它看不见；Vue 3 的监听是"装在对象外面的"，所以怎么改都逃不掉。

回忆卡 2 · 合上材料，用自己的话讲一遍

如果对方说「那 Vue 3 全面优于 Vue 2 吧」，你怎么接？

讲完了，展开对照

不要顺着说"对"，这样答会显得没有判断。分三点接：

  1. 响应式这块确实全面更好：三个坑都没了，初始化也更快，不用再记 $set 那套补救写法。
  2. 但 Proxy 有硬代价：旧浏览器完全不支持，而且没法用语法糖降级——不像箭头函数可以编译成普通函数。所以 Vue 3 直接放弃了 IE。如果项目有老浏览器要求，这就不是"优不优"的问题，是"能不能用"。
  3. 而且 Vue 3 变快的主要原因不在这里：真正的性能提升来自编译时的静态提升和补丁标记，Proxy 只是其中一环。把功劳全归给 Proxy，说明理解还停在表面。

收尾："所以选型要看约束。新项目当然用 3，老项目升级要先算清兼容成本。"

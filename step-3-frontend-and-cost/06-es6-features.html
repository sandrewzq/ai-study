06 · ES6 语言特性

这一组是"基础题"，但基础题最容易答得平淡。这一页的做法是：把"我背过特性表"变成"我知道它解决了什么"—— 同样的知识点，后者听起来完全不同。

SH-22SH-23SH-24SH-25SH-26SH-27KJ-4
读之前

需要知道"函数""对象""原型"大概是什么。如果 class、Promise 这些你只是见过、没自己写过，这一页正好把它们串一遍。术语不熟先看 00 · 先认识这几个词。

第一遍（4 分钟）看主图——记住"ES6 到底解决了什么问题"。
第二遍（15 分钟）读第 2、3 节，这两节是真正会被追问的。
第三遍做页尾回忆卡，然后把一段 ES5 代码改写成 ES6，反过来也行。

0. 先看一个场景

对方问：「ES6 有哪些常用特性？」

很多人立刻开始报菜名：let、const、箭头函数、模板字符串、解构、展开运算符、Promise、class、模块化……

报完，对方"嗯"了一声，换下一题。你没答错，但也没拿到分。

因为这道题的货不在"列出多少个"，而在你能不能说出这些特性各自解决了什么麻烦。同样是讲箭头函数：

❌ 背特性✅ 讲问题
"箭头函数语法更短，而且没有自己的 this。" "以前写回调，里面的 this 指谁完全看谁调用的，得靠 var that = this 这种土办法兜住。箭头函数直接用外层的 this，这个坑就没了——代价是它不能用来定义需要自己 this 的方法。"

右边这段话多讲了两句，但同时暴露了三件事：你踩过那个坑、你知道新特性的边界、你能讲清取舍。

主图 · ES6 不是在加语法糖，是在补三个老麻烦

变量作用域混乱、异步难写、代码无法拆分

这张图在说什么：ES6 的特性可以分成两批——一批是真正解决老麻烦的（作用域、异步、模块），一批是让写法更短的（模板字符串、解构、展开）。

答"有哪些常用特性"时，先说第一批并讲清解决了什么，第二批一句带过。这个组织方式本身就说明你不是在背清单。

颜色含义： ES5 的老问题 ES6 的解法 语法便利类

1. ES5 和 ES6 的构造函数（SH-24、SH-25）

这两题问的是同一个东西的两种写法。关键在于答出"新写法是语法糖，但有几处不一样"——只说"一个是 function 一个是 class"会被认为理解很浅。

ES5 的写法ES6 的写法
怎么定义 定义一个普通函数，用的时候前面加 new。约定俗成首字母大写，但那只是约定——不加 new 直接调也不会报错，只会出莫名其妙的问题。 用 class 定义，里面写构造函数和各个方法。不加 new 直接调会直接报错——这是它比 ES5 严谨的地方。
方法放哪 挂在原型上，写法是把构造函数的名字再写一遍。 直接写在 class 里面，看起来像对象字面量，但实际仍然是挂在原型上。
怎么继承 要手动把子类的原型指向父类的实例（或用一个中间对象过渡），再补回构造函数指向。步骤多、容易漏。 extends 一行搞定，super 调用父类构造函数。原型链的接线工作框架替你做了。
本质 两者最终都落到原型上，运行时的对象结构是一样的。class 是语法糖——它没有引入新的对象模型，只是把原型操作包装得更安全、更易读。
这题的加分点

答出"语法糖"之后，再补三处"糖之外"的真实差异，就完整了：

  • 必须加 new：class 当普通函数调用会直接报错，避免了 ES5 里"忘了 new 导致变量挂到全局"的坑。
  • 不会提升：函数声明会提升，但 class 必须先定义后使用。
  • 方法不可枚举：挂在原型上的方法默认不出现在遍历里，这和 ES5 手动挂的行为不一样。

最后收一句："所以可以理解成——同样的原型模型，换了一套更不容易写错的语法。"

对方追问：「那你平时写代码会区分 ES5 和 ES6 吗？」（SH-26）

这题看起来随口一问，其实在看你知不知道"写的代码"和"跑的代码"是两回事。

答法：写的时候不区分，但要清楚它们编译后是什么。

  • 现在项目里都直接写新语法，由打包工具统一转成浏览器能跑的旧语法，所以写的时候不用忌讳。
  • 但必须知道转译是有边界的：语法可以转（箭头函数转成普通函数），而一些内置的新对象和方法是转不出来的——那些只能靠额外的兼容库去补，或者干脆不用。这一条和下一份（浏览器兼容）直接相关。
  • 看老项目代码时当然要认得 ES5 那套写法，尤其是继承那几行。

2. 什么是柯里化（SH-23）

这题很多人只会背定义："把接收多个参数的函数变成一系列接收单个参数的函数。"背完就没了。

其实柯里化不是语言特性，是一种常用手法，它的价值在于参数复用和延迟执行。讲清这两点，这题就答透了。

它带来什么什么意思什么时候真的用得上
参数复用 固定住前面的参数，拿到一个"预设好的"新函数，后面反复用。 比如写日志：先固定好模块名，之后调用只需要传内容。或者接口请求：先固定好基础地址。
延迟执行 参数给不齐就先不执行，返回一个等着接收剩余参数的函数。 需要先把函数攒起来、等条件满足再触发的时候。
方便组合 都变成单参数之后，更容易把小函数串成管道。 数据处理流程：一串小函数依次加工同一个值。
被追问「你实际用过吗」怎么办

诚实一点最安全。可以说："我没有专门写过通用的柯里化工具函数，但日常代码里这种思路一直在用"——然后举一个你真写过的例子：

  • 事件处理里先固定住某个参数（比如行的 id），返回一个只等事件的函数。
  • 用 bind 固定参数——bind 本身就是柯里化的一种形式，这句话说出来很加分。

不要硬编一个"我在项目里实现了柯里化工具"，被追问实现细节会很尴尬。

3. Promise / 展开运算符 / 箭头函数 / 模板字符串（SH-27）

这题列了四样东西让你确认——语气上是在核对基础，但答的时候可以借它展示深度。每样用一句"它是什么 + 解决什么 + 一个注意点"的结构说。

特性解决什么一个能显出你踩过坑的注意点
Promise 把层层嵌套的回调改成链式调用，错误可以统一在一处捕获。 它一旦确定就不会再变（成功或失败只认第一次）。另外并发请求要用"全部完成"或"任意一个完成"这类组合方法，别在循环里一个个等——那样会串行，白白变慢。
箭头函数 写法更短，且没有自己的 this，直接用外层的。 正因为它没有自己的 this，不能用来定义对象方法或需要动态 this 的场景；也不能当构造函数用。
模板字符串 拼字符串不用再加号，可以直接嵌变量，还能写多行。 拼接用户输入时要注意转义——直接插进 HTML 会有安全风险，得先处理。
展开运算符 把数组或对象"摊平"，常用于复制、合并、传参。 它只做浅拷贝——嵌套的对象仍然共享引用。改副本里的深层字段，原对象也会变。这是最常见的误解，很多人以为展开就是深拷贝。

4. WebAssembly 了解过吗（KJ-4）

这题大概率是"顺口一问"，答不上来不致命，但答得清楚会让对方记住你。

核心一句话：它让用 C++、Rust 这类语言写的代码，能在浏览器里以接近原生的速度跑。

维度怎么理解
它是什么 一种浏览器能直接执行的二进制格式。它不是给人写的语言，而是其他语言的编译目标——你用别的语言写，编译成它，浏览器负责跑。
为什么要它 JS 是解释执行的，做密集计算（视频编解码、图像处理、物理仿真、压缩解压）时会力不从心。这类活儿搬到这种格式里跑，速度快得多。
和 JS 什么关系 互补，不是替代。它不擅长操作页面（碰 DOM 反而慢），所以典型做法是：重的计算交给它，页面的渲染和交互仍然用 JS，两边来回传数据。
什么时候用 只有当你的页面里真的有一块算得很慢、而且这块逻辑能用别的语言现成实现时（比如已经有成熟的 C 库），才值得引入。为了用而用是负收益——它体积不小，还得处理两边数据传递。
这题的加分点

最后补一句判断标准，就从"我听说过"变成了"我知道什么时候该用"：

「我会先问瓶颈是不是真的在计算上。如果是网络、渲染、或者频繁的数据传递，换成它没有意义。确实是计算密集、而且已经有现成的库，才值得引入——否则体积和维护成本都不划算。」

5. 讲解骨架（看懂之后再背）

「ES6 有哪些常用特性 / ES5 和 ES6 的区别」

【结论】我习惯把它们分两批看：一批是解决老问题的——块级作用域解决变量提升和循环闭包，Promise 解决回调嵌套，模块机制解决代码拆分；另一批是让写法更短的——模板字符串、解构、展开运算符、class、默认参数。

【重点展开】箭头函数值得单独说：它没有自己的 this，用的是外层的，所以解决了回调里 this 指向混乱的问题；代价是不能当对象方法或构造函数用。

【构造函数】ES5 用普通函数加 new，方法挂原型，继承要手动接原型链；ES6 用 class 加 extends 和 super。但本质是语法糖，运行时还是原型那套——差别在 class 必须用 new 调、不会提升、方法不可枚举。

【实际用法】写代码时不区分版本，打包工具会统一转译。但要知道转译有边界：语法能转，一些内置的新对象和方法转不出来，得靠兼容方案补。

【数字/经验】展开运算符我用得最多，但踩过一次坑：它是浅拷贝，我用它复制了一份配置对象，改副本里的嵌套字段，结果原对象也跟着变了，排查了半天。

【权衡】新语法能提效率，但也别滥用。比如箭头函数虽然短，但在需要动态 this 的地方用它会出问题——知道它什么时候不该用，比知道它怎么写更重要。

回忆卡 1 · 合上材料，用自己的话讲一遍

用 ES5 和 ES6 各写一遍"一个用户类，继承自一个人"，并说出一处非语法层面的差异。

讲完了，展开对照

ES5：先定义 function Person(name){...}，把方法挂到 Person.prototype 上；子类里先调用父类构造函数拿到属性，再把子类原型指向一个以父类原型为原型的对象，最后别忘了把原型的构造函数指回子类自己（这一步最容易漏）。

ES6：class Person {...}，子类写 class User extends Person，构造函数里用 super(name) 调父类。原型链的接线由语法自动完成。

非语法层面的差异（挑一个说就行）：

  • 必须用 new：ES5 忘了加会静默出错（属性挂到全局），ES6 直接抛错。
  • 提升行为不同：ES5 的函数声明会提升，ES6 的 class 不会。
  • 方法可枚举性不同：ES5 手动挂的方法默认可枚举，class 里的方法不可枚举。

收一句："两者最终都落到原型上，class 是更安全易读的写法。"

回忆卡 2 · 合上材料，用自己的话讲一遍

用展开运算符复制一个对象，改副本的嵌套字段，原对象会变吗？为什么？

讲完了，展开对照

会变。展开运算符只做浅拷贝：它把第一层的字段复制到新对象里，但如果某个字段的值本身是个对象或数组，复制过去的是同一个引用，不是一份新数据。

所以：改第一层的字段，互不影响；改嵌套进去的字段，两边一起变。

要真正独立，得逐层复制，或者用一个能处理嵌套的深拷贝方式。但要注意：深拷贝不是无脑用就好——它在处理循环引用、特殊对象（日期、正则）时会出问题，而且数据大时开销明显。很多时候"避免改原对象"比"复制一份"更简单。

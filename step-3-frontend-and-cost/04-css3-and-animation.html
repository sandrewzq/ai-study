04 · CSS3 与动画

这一组题看起来是"背特性"，其实只考一件事：做动画时，你知道该用 CSS 还是 JS 吗？ 答对这题的前提，是理解浏览器渲染的三个阶段。

SH-1SH-2SH-3SH-4
读之前

需要知道 CSS 选择器大概怎么写、什么是"样式属性"。不要求你会写动画——这一页从零讲起。完全没碰过的话先看 00 · 先认识这几个词。

第一遍（4 分钟）只看主图——记住"改哪个属性决定快慢"。
第二遍（12 分钟）读第 3 节，那是这一组题真正的分界线。
第三遍做页尾回忆卡，然后打开浏览器控制台，手动改几个属性看渲染帧。

0. 先看一个场景

要做个"消息卡片从右边滑入"的效果。你随手写了三行：

第一种写法

transition: left .3s;　然后 JS 里改 el.style.left = '0'

效果对了。但上线后有人反馈：卡片滑入的时候，整个页面会卡一下，尤其是列表里有几十条消息时。

你把 left 换成 transform: translateX()，同样的视觉效果，卡顿没了。

原因就是这一页要讲的：同样是"从一个位置移动到另一个位置"，改 left 和改 transform 在浏览器内部走的是两条完全不同的路。

主图 · 决定动画快慢的不是"用 CSS 还是 JS"

而是你改的属性，让浏览器做到哪一步

这张图在说什么：动画卡不卡，取决于你改的属性会让浏览器做到哪一步。改 left 要重新算布局，改 transform 常常只需要合成——后者可以交给显卡，不占主线程。

记住这个，第 3 节那道"CSS 动画和 JS 动画有什么区别"就自然有答案了：真正的分界线不是"谁来实现"，而是"改的是不是那两类便宜属性"。

颜色含义： 渲染阶段 代价最高 代价中等 代价最低

1. 「CSS3 你常用哪些」（SH-1）

这题没有标准答案，但有个陷阱：很多人一开口就是"圆角、阴影、渐变"——这些是视觉装饰，说出来显得你只用过皮毛。

更稳的答法是按用途分组，让人听出你的使用场景：

用途常用特性用在哪
布局 弹性布局（flex）、网格布局（grid） 这是最该先说的，因为它体现的是"我天天在写页面"，而不是"我背过特性表"。一句话：简单的一维排列用弹性布局，复杂的二维网格用网格布局。
响应式 媒体查询、相对单位（rem / vw）、clamp() 做流体字号 适配不同屏幕宽度。比"我写了两套样式"更专业的说法是"用相对单位 + 媒体查询做断点"。
动画与过渡 transition、transform、animation + @keyframes 交互反馈和入场效果。注意区分：状态之间平滑变化用过渡，需要循环或多段的关键帧用动画。
变量与主题 自定义属性（--xxx）配合 var() 做主题色和深色模式。这个点很多人忽略，但说出来很加分——它说明你考虑过可维护性，不只是"把样式写出来"。
视觉装饰 圆角、阴影、渐变、毛玻璃 放最后说，一带而过即可。
为什么顺序很重要

同样列五个特性，按"布局 → 响应式 → 动画 → 变量 → 装饰"说，听起来是"我在做工程"；按"圆角 → 阴影 → 渐变 → 旋转 → 缩放"说，听起来是"我照着教程做过几个效果"。

内容差不多，组织方式决定了对方怎么判断你。

2. 渐变 / 旋转 / 缩放到底怎么用（SH-2）

这几样都属于"用过就会、没用过就说不出细节"的类型。答的时候说清"它是什么 + 我拿它做过什么"就够，不用背语法。

特性一句话说清它典型用途
渐变 让背景从一种颜色平滑过渡到另一种，不用图片。线性渐变按方向过渡，径向渐变从中心向外扩散。 按钮、卡片背景、骨架屏的加载动效。最大的好处是省一张图，体积小还能随容器自适应。
旋转 / 缩放 / 位移 都属于 transform，它们不改变元素在布局里占的位置——只是在画的时候换了样子。 加载转圈、hover 放大、滑入滑出。"不改变布局位置"这一点很关键，正是它让这类改动更便宜。
关键帧动画 @keyframes 定义几个时间点上的样子，浏览器负责补中间过程。可以设循环、方向、缓动。 呼吸灯、脉冲、循环漂浮、多段入场。需要"反复播放"或"多个阶段"时用它，单纯两个状态之间的变化用过渡就够了。
一个容易被追问的点

对方可能接着问："那 transform 会不会影响旁边元素的位置？"

答案：不会。它作用在渲染阶段，元素在文档流里占的位置不变，所以旁边的元素不会跟着挪。这正是它便宜的原因——不需要重新计算布局。

反过来，如果你改 width 或 margin，旁边元素会被挤走，浏览器就必须重新算一遍布局。

3. CSS 动画和 JS 动画的区别（SH-3、SH-4）

这是这一组的主菜。先说一个反常识的结论：两者的核心区别不是"谁来实现"，而是"改的是哪类属性"。

因为 JS 也可以去改 transform——那样它同样便宜。所以真正的区别在下面这三个维度：

维度CSS 动画JS 动画
谁来驱动 浏览器自己按样式规则跑，不占 JS 主线程。改的是那两类便宜属性时，还能交给显卡。 一般用 requestAnimationFrame 每帧算一次位置，跑在 JS 主线程上。主线程一忙（比如在算数据），动画就掉帧。
能不能中途干预 弱：可以暂停、改速度，但中途改目标值、动态调轨迹很别扭。 强：随时能读当前位置、改目标、反转、按物理规律算（弹簧、惯性）。
适合什么 状态之间固定的过渡：hover、展开收起、入场退出。 需要"跟着手势走"的：拖拽、滚动联动、跟随鼠标、路径动画。
这题的加分点

大多数人会答"CSS 性能好、JS 灵活"，这不算错但太浅。加上这一句立刻不一样：

「其实用 JS 改 transform 一样快，因为决定开销的是属性而不是驱动方式。CSS 的真正优势是不占主线程——主线程在忙着处理数据时，CSS 动画照样流畅；而 JS 动画会和业务逻辑抢主线程。所以我的做法是：能用 CSS 的就用 CSS，只有需要跟着手势实时算的时候才上 JS。」

对方追问：「那为什么有时候 JS 动画反而更流畅？」

这通常发生在JS 动画用了便宜属性（transform），而 CSS 动画用了贵属性（left）的时候。所以不是"JS 更快"，是"那个 JS 写对了、那个 CSS 写错了"。

还有一种情况：某些浏览器对复杂的关键帧动画（很多元素、很多属性同时变）调度得不好，此时 JS 自己控制节奏反而更稳。但这是特例，不是通例。

回答时把结论收在标准上："判断标准是改的属性，不是驱动方式。先看属性，再看谁来驱动。"

对方追问：「那到底该用哪个？你的选择标准是什么？」

给一个可执行的标准，比说"看情况"强得多：

  1. 效果是固定的两三个状态之间切换吗？是 → 用 CSS 过渡，最省事也最流畅。
  2. 需要循环或多段关键帧吗？是 → 用 CSS 动画。
  3. 需要跟着用户的手势实时变吗？是 → 用 JS，但仍然只改便宜属性。
  4. 动画里有大量元素各自独立运动（比如上百个粒子）？→ 那就别用 DOM 了，考虑用 Canvas，见下一份。

4. 讲解骨架（看懂之后再背）

「CSS3 你常用哪些 / CSS 动画和 JS 动画有什么区别」

【结论】CSS3 我按用途分：布局用弹性布局和网格布局，响应式用媒体查询和相对单位，动画用过渡和关键帧，主题用自定义属性管理颜色；圆角阴影渐变这些装饰性的也用，但优先级低。

【动画实现】CSS 侧就是 transition 做状态过渡、@keyframes 做多段或循环；JS 侧一般用 requestAnimationFrame 每帧改样式。

【区别】关键要说清一点：区别不在"谁来实现"，而在"改的是哪类属性"。改宽高、位置这些会触发重新布局；改 transform 和 opacity 通常只需要合成，可以交给显卡。JS 改 transform 一样便宜。

【真正差异】CSS 动画不占主线程，所以业务逻辑忙的时候它照样流畅；JS 动画跑在主线程上，会和业务逻辑抢资源，但胜在可以实时干预——跟着手势、按物理规律算。

【数字】有一次消息列表滑入卡顿，原因是用了 left 做位移，每帧都要重新布局；换成 transform 之后，几十条消息同时入场也不掉帧。

【权衡】所以选择标准是：能用 CSS 就用 CSS，需要实时跟随手势才用 JS——而且无论哪种，都优先用 transform 和 opacity。

回忆卡 1 · 合上材料，用自己的话讲一遍

一个元素要从屏幕左侧滑到中间，下面两种写法效果一样，性能一样吗？为什么？
① 用过渡改 left　② 用过渡改 transform

讲完了，展开对照

不一样，差很多。

  • 改 left：位置变化会影响布局，浏览器每一帧都得重新计算元素位置（甚至整页），再重新绘制，最后合成。元素多的时候，这些计算都在主线程上做，就容易掉帧。
  • 改 transform：它不改变元素在布局里占的位置，只是渲染时换个画法，所以通常跳过布局和绘制，直接合成，这一步可以交给显卡。

一句话：同样的视觉效果，一个要重算布局，一个只要显卡挪一下图层。

回忆卡 2 · 合上材料，用自己的话讲一遍

「CSS 动画比 JS 动画性能好」——这句话对吗？怎么答才完整？

讲完了，展开对照

不完全对，要拆开说。

  1. 先说条件：性能取决于改的属性。两类属性便宜（transform 和 opacity），其他大多更贵。JS 改便宜属性一样快。
  2. 再说 CSS 的真实优势：它由浏览器自己驱动，不占 JS 主线程。所以主线程在忙着算数据时，CSS 动画仍然流畅；JS 动画会和业务逻辑抢主线程。
  3. 最后说 JS 的不可替代：需要跟着手势实时变、按物理规律算（弹簧、惯性）、随时中断反转的动画，CSS 做不了或很难做。

收尾："所以我的标准是能 CSS 就 CSS，需要实时跟随才上 JS，但两边都优先用 transform 和 opacity。"

# 学习资料规范

> 这份文档规定学习材料**怎么写、怎么排版、怎么自检**。新增或修改任何一页材料前先看它。
> 目标读者定位：**接触过 AI、但很多概念不懂、没自己写过**。

---

## 一、文件组织

```
ai-study/
├── index.html                   ← ★ 总入口（所有页面的侧栏「往上」都通向它）
├── README.md
├── assets/
│   ├── style.css                ← 全部材料共用
│   ├── app.js                   ← 交互层（搜索 / 打勾 / 配色 / 回到顶部），可关
│   └── search-index.js          ← 搜索索引，由 _dev/build-search.js 生成
├── reference/                   ← 两个查询页（不是学习材料）
│   ├── plan.html                ← 学习计划全文（由 plan/roadmap.md 生成）
│   └── questions.html           ← 242 题题库（由 plan/questions.md + 各材料页生成）
├── plan/                        ← 只放源文件与开发文档，不进站点导航
│   ├── roadmap.md               ← 学习计划的源文件（改内容改它）
│   ├── questions.md             ← 题库的源文件（改内容改它）
│   ├── spec.html                ← 本文档的渲染版（gen-plan-html.js，开发文档、不进站点导航）
│   └── spec.md                  ← 本文档
├── step-1-foundation/           ← 步骤 1
│   ├── index.html               ← 该步骤的材料目录
│   ├── 00-key-terms.html        ← 前置页，不属于任何域
│   └── 01~09-*.html             ← 正式材料
├── step-2-systems/              ← 步骤 2
│   ├── index.html
│   └── 00~10-*.html
└── _dev/                        ← 自检与生成脚本（零依赖）
```

**根目录只放 `index.html`、`README.md`、`LICENSE`、`.gitignore`、`.nojekyll`**，其余一律进子目录。

> **根目录只有一个页面，是刻意的**：全站 68 页里只有它是「入口」，读者拿到的任何一条链接都该从这里开始认路。学习计划与题库虽然也是全站级的页面，但它们是**查询用的参考页**，不是第二个、第三个入口——放进 `reference/` 之后，「往上」一律通向总目录，导航不会出现「两个都像首页」的歧义。

> 页型判据是**名字清单**（`_dev/pagekind.js` 的 `kindOf` 读 `NAV.refs`）而不是目录位置：入口页 = 根目录的 `index.html`；参考页 = `NAV.refs` 点名的那两条路径（`reference/plan.html` / `reference/questions.html`，侧栏两段、豁免字数与骨架）；子目录的 `index.html` = 目录页；其余 = 材料页（12 项骨架 + 字数区间）。**换目录只改 `NAV.refs` 一处**，`kindOf` / `hrefFrom` / `apply-nav.js` / `navcheck.js` / `link-questions.js` 全都从它派生。早期版本把「参考页」判成「根目录下任何非 `index.html` 的页」，那是一条**位置事实**而不是名字——两个参考页一搬进 `reference/`，判据就静默失效（它们会被当成材料页走一遍）。

- 编号 `NN-topic.html`（英文小写连字符），数字即阅读顺序；**页面标题和正文仍用中文**
- 子目录名、文件名一律英文，避免 URL 出现 `%E4%BB%80%E4%B9%88` 这类编码
- `_` 前缀 = 开发/辅助文件，统一收在 `_dev/`，不进入目录页的卡片列表
- **导航外壳、页内目录、搜索索引都不手写**，跑 `_dev/` 里的生成脚本（见第五节）
- 每份材料只覆盖**一个知识主题**，且必须能对应到学习计划里的域和题号

### 导航约定（全站统一外壳）

**核心原则：一个导航面。** topbar 只报「我在哪」，一个链接都不放；所有跳转只在侧栏。
（踩过的坑：同一组链接在 topbar 和侧栏各写一遍，58 个材料页上两处一字不差，交互分散、看着乱。）

```
┌───────────────────┬──────────────────────────────────┐
│ 顶栏（sticky）· 只报位置 + 两个工具按钮，不放链接    │
│ 步骤 2 · 第 1/12 份 ｜ C 域 · 上下文治理与流式通信   │
├───────────────────┼──────────────────────────────────┤
│ 侧栏（唯一导航）  │ 正文                             │
│                   │                                  │
│ 往上              │                                  │
│   ← 总目录        │                                  │
│ 这一层            │                                  │
│   步骤 2 · 做系统 │  ← 材料页上这条是链接，回材料目录│
│   00 … 10         │                                  │
│ 参考              │                                  │
│   学习计划全文    │                                  │
│                   │                                  │
└───────────────────┴──────────────────────────────────┘
```

**侧栏固定三段。** 这是**材料页 / 目录页**的骨架；入口页和参考页是仅有的两个例外，
各有一份写明的理由，在下面「三个全站级页面」一段。别把「固定三段」读成全站每一页都长这样：

| 段 | 装什么 | 每个页型各有什么 |
|---|---|---|
| **往上** | 回上层 | 材料页 / 目录页：`← 总目录`（只有这一条） |
| **这一层** | 同级页面 | 材料页 / 目录页：步骤名 + 该步骤全部材料 |
| **参考** | 跨页参考 | 材料页 / 目录页：`学习计划` + `题目索引`（两条） |

**步骤名就是「回材料目录」的入口**，不要再单独放一条 `← 材料目录`——那是同一个页面写两遍。
两种页型区别在于是链接还是纯文本：

| 页型 | 步骤名 | 为什么 |
|---|---|---|
| 材料页 | `<a class="grp sub" href="index.html">步骤 2 · 做系统</a>` | 点了回材料目录 |
| 目录页 | `<div class="grp sub">步骤 2 · 做系统</div>` | 那一步就是本页，做成链接就是自链接 |

**这两种身份必须在静止状态就分得出来**，不能只靠 `:hover`。宽屏下 `.item` 没有边框，
全是一行 `--fg` 文字，于是「步骤名」和它下面第一份材料长得一模一样——一个能点、一个不能点，
读者无从判断（这是实际收到的反馈）。所以定了两条：

1. **贯穿整个侧栏的读法：`--fg` 的行能点，灰色的行是标签。** `div.grp.sub`（本页）降到 `--muted`，
   和「往上 / 这一层 / 参考」那几个分区标题同一副面孔，不再装成可点的条目。
2. **可点的那种补一个 `←`**，和「往上」段的 `← 总目录` 用同一套语言——它干的本来就是同一件事
   （往上走一层）。`←` 由 CSS `::before` 出，HTML 不用改。

窄屏（≤980px）本来就没这个问题：`.item` 是带边框的 chip，标签没有边框，一眼能分。

**三层结构**（像屏幕栈一样，每层都有明确的返回）：

| 层级 | 页面 | 侧栏内容 |
|---|---|---|
| 1 · 着陆页 | `index.html` | 站点级导航：本页三个区块 + 各步骤 / 专题目录页入口（3 组 10 项）；它是最外层，没有「往上」 |
| 2 · 步骤目录 | `step-N-xxx/index.html` | 往上（总目录）+ 步骤名（纯文本）+ 该步骤的材料列表 + 参考 |
| 3 · 材料页 | `step-N-xxx/NN-topic.html` | 往上（总目录）+ 步骤名（链接回材料目录）+ 该步骤的材料列表（当前页高亮）+ 参考 |

**不许出现指向自己的链接。** 目录页上那一步就是本页，所以步骤名不做成链接——当前页由正文的大标题表达；
材料页上的当前页用 `.item.cur` 高亮，**每个材料页有且只有一条** `.item.cur`。

**侧栏只装一种东西：站点级导航。** 入口页里嵌着一份完整的学习计划（有自己的 h1 和章节编号），
那份计划**自带目录**（正文开头的 `.toc` 块，紧随它的 h1），不占用侧栏。

这条是踩过坑总结出来的：侧栏一旦同时服务两份文档，就会出现三个毛病——
**用途横跳**（本页锚点和跨页链接交替出现）、**父子平铺**（「学习计划全文」和它的 11 个章节变成平级分组）、
**篇幅失衡**（低频的计划目录和常用的材料入口各占一半）。读起来像好几个目录堆在一起，不像一个整体。

判断标准：**侧栏里每一项点了之后，要么跳到另一个页面，要么跳到本页的某个区块；
同一批内容的父项和子项，不要拆成平级的分组。**

**实现要求**：

- 布局用 `.layout`（grid 两栏）+ `.sidenav`（sticky），**不要用绝对定位**
- 侧栏三段的分区标题用 `.grp`，「这一层」下的步骤名用 `.grp.sub`（紧贴分区标题，不占一整段间距）；
  窄屏时 `.grp.zone` 跟它的链接同排、`.grp.zone.mid`（「这一层」）隐藏——它是全站唯一占高度的分区标题
- **侧栏里每一行的可点性都要在静止状态看出来**：`--fg` = 可点，`--muted` = 标签。
  悬停反馈只能当补充，不能当唯一线索——读者不会为了判断能不能点先把鼠标扫一遍
- **`<header class="topbar">` 里不许出现 `<a>`**：只保留 `<span class="crumb">` 和一组 `<button>` 工具。
  按钮不算导航——它们不指向任何页面，不参与「我在哪」的表达，所以不受上面「一个导航面」的约束；
  侧栏仍然是全站唯一的导航面。工具按钮由 `assets/app.js` 在运行时插入（无 JS 时不出现），
  所以顶栏还是一条位置栏，不是第二条导航栏
- 窄屏（≤980px）自动降级：侧栏变成可换行的 chip 列表，不再是侧边栏
- 窄屏下**栅格列必须写 `minmax(0, 1fr)`**，写 `1fr` 会被宽表格的 min-content 撑破
- 宽表格在窄屏改为横向滚动（`display: block; overflow-x: auto`），不要撑宽整页
- 所有链接和折叠标题要能用键盘 Tab 到达，且有可见的焦点样式（`:focus-visible`）

侧栏整体由 `node _dev/apply-nav.js` 生成（可重入，重复跑结果一致），
导航规则由 `node _dev/navcheck.js` 回归。

### 交互层（渐进增强）

站点是「双击打开」的静态 HTML，但**纯静态 ≠ 只能线性翻页**：68 页、242 题、每页四五千字，
没有搜索就只能靠侧栏一页页点。所以有一层很薄的交互（`assets/app.js`，约 500 行，无依赖）。

**唯一的硬约束是渐进增强：禁掉 JS，页面必须照常可读。** 这决定了四件事：

| 能加 | 不能加 |
|---|---|
| 运行时插按钮（搜索 / 配色 / 回到顶部 / 展开全部） | 把内容藏在 JS 后面（无 JS 就白屏） |
| 用 `localStorage` 记状态，失败就退回内存 | 要求 localStorage 一定可用（`file://` 下会抛错） |
| 用 `<script src>` 加载索引 | 用 `fetch()` 读本地文件（`file://` 下被拦） |
| 用 `<a class="qref">` 静态写好题号链接 | 运行时 JS 装饰出链接（这样 `checklinks.js` 就验不到了） |

**题号反查**：`link-questions.js` 的 `CONSUMERS`（`index.html` / `reference/plan.html` / `reference/questions.html`）
里每一处题号都是 `<a class="qref" href="…">`，指向讲这道题的材料页（共 399 处）。
映射读各材料页的 `.qbadges`，**每个题号必须有且只有一个材料页认领**，
漏写或重复都直接报错不写文件。由 `node _dev/link-questions.js` 生成，
`checklinks.js` 顺带把这几百条链接全验一遍。

> **href 要按「这段 html 落到哪一页」现算**：三个消费者不再同层（入口页在根、两个参考页在
> `reference/`），同一个题号在三页里的相对路径不一样。`linkify(html, owners, page)` 的第三个
> 参数是**必需的**（漏传直接抛错），内部走 `pagekind.hrefFrom`。曾经的做法是把 `owners` 里
> 那份仓库根起算的路径直接当 href——只在「三个消费者都在根目录」时凑巧成立。

> 覆盖面是**比出来的、不是数出来的**：`CONSUMERS` 里引用的题号集合与 `/材料页认领的题号集合`
> 必须完全相等，两个方向都查。不要改成「看某一页里出现了多少个」——那个写法要靠
> 「某一页恰好含全集」这个巧合才成立，计划正文一搬家就会静默失效。

**题号落点**：链接末尾带页内锚点（`…/03-vector-store-and-index.html#s5`），
点 `JR-7` 直接到答它的**那一节**，不是材料页顶部。落点由 `qids.buildLandings()` 推导，
**真值只有一个：h2 标题里写的题号**——不另开一张映射表，两份必然漂。

| 层 | 判据 | 落在哪 |
|---|---|---|
| 一层（精确） | 题号写在该页某个 h2 标题里（`1. 用户量怎么答（ML-11）`） | 那一节的 `#id` |
| 二层（兜底） | 标题里没写 | 该页「讲解骨架」那一节（09 那页认「完整参考回答」） |

**这个约定本来就存在**（22 页一直在标题里写题号），落点只是把它读出来用，
再把没写的页补齐。**二层兜底不是欠账**：讲解骨架就是这一页所有题的答法，
对「整页才是答案」的概念页（`01-what-is-rag` 那类，正文节在讲别的问题）来说它就是正确答案。

> **别把落点切到骨架段内部。** 讲解骨架是**一页一段**、不是一题一段，页内的
> `<details class="ask">` 追问块与题号也**不是一一对应**（03 页 3 个 ask 的 summary
> 并不是那 3 道题的题面）。落点只到 h2 节这一级；硬切到段内只会指错地方。

同一个题号写在**两节**标题里是允许的，落点取文档顺序里第一个。复合题真的会这样：
`YC-5`「技术架构：你怎么拆模块？数据怎么流转？技术选型怎么做？」一题三个问号，
两节各答一部分、两节都该写它。**起初这里当成错误抛，磁盘上立刻撞到反例**——
强行只许写一处，等于逼作者少声明「这节也答了这题」，是拿检查器去扭曲内容。

`buildLandings()` 在**写盘之前**查三条不变量：每个被认领的题号都能解析出落点、
写了题号的 h2 有 `id`、**标题里的题号属于本页 `.qbadges`**。最后一条捞到过真的硬伤：
`02-self-assessment` 的「优点怎么答（FN-8、**FN-9**）」里 `FN-9` 是别页的题，
落点会指错页。这条不影响 A 边（A 看 `.qbadges`，不看标题）。

**页内目录**：材料页第一个 `<h2>` 之前放一个正文 `.toc` 块（不是放侧栏——理由见上），
由 `node _dev/add-toc.js` 从各页 h2 生成。章节少于 3 个的页、目录页、入口页、参考页豁免
（后两种自己就带一个整页级的目录，再插一个就是两个目录打架）。
`.toc` 的条目**就是各节标题的原文**，所以 CSS 里 `.toc ol` 关掉了列表序号——
大多数标题自带编号（「0. 先看一个场景」），留着序号会印成「1. 0. 先看一个场景」。

**站内搜索**：索引是 `assets/search-index.js`（`window.SITE_INDEX`，68 页 / 346 个章节 / 约 137 KB），
由 `node _dev/build-search.js` 生成，第一次按 <kbd>/</kbd> 或点搜索按钮时才加载。
**索引里必须带正文摘录**（每节 100 字符）——只索引标题的话，
读者记得住的概念（比如「虚拟滚动」）八成搜不到，它只出现在正文里。

**完成标志打勾**：`.checklist` 是「完成标志」清单，在 **7 个目录页 + 5 个 `00-` 导读页 +
1 个自测页 + 题目索引页**上，共 14 页（材料页没有这个清单，它的页尾是 `.recall` 回忆卡）。
每条前面由 JS 插一个 `.ck` 真按钮（带 `aria-pressed`），清单顶上显示「已掌握 n/N」。
318 条里只有 `reference/questions.html` 那份 242 题的清单带题号，直接用题号当 id（`q:JR-5`）——
那份清单由 `plan/questions.md` 生成，条目会随源文件增删改序，用题号当 id 才不会丢勾；
其余 13 页的 76 条没有稳定标识，用条目文字的哈希（`h:…`）——文字改了就算新的一项，旧勾留着不碍事。

> 题号当 id 还意味着**同一个题号在哪一页都是同一项**。今天 242 个 `q:` id 只在
> `reference/questions.html` 上出现一次，所以「翻到另一页发现勾已经打上了」不会发生；
> 但真把 242 题的清单再复制到第二页，两页的勾会立刻联动——那是同一道题被算了两次，
> 不是 bug，是「一题只该有一处可勾」这条规矩被破了。

> **改完成标志的文字 = 换一个 id = 老勾消失**，这是哈希方案自带的代价，一般可以接受
> （措辞都改了，那一项本来也不是同一件事了）。但重编号章节时要注意：正文里那些
> 「第 N 节…」的完成标志会跟着改字，读者攒下的勾会静默少一个。v2 就这么清掉过一条，
> 处理办法是在 `assets/app.js` 里放一张 `LEGACY_CK_IDS` 老 id → 新 id 的迁移表，
> 读盘时改写一次。**这类改动不会自检报错**——`--check` 只看 HTML，看不见 localStorage。

> 改交互层时记住 `--topbar-h`：它是锚点落点的唯一依据（`html{scroll-padding-top}` 和侧栏粘顶都用它）。
> CSS 里给了两档静态值供无 JS 时兜底，有 JS 时 `app.js` 会量真实高度写回去。
> **往顶栏加东西之前先量**——按钮做大了会把顶栏撑高一格，而窄屏 + 长 crumb 时它本来就会折成两行。

**入口唯一**：全站只有一个着陆页（`index.html`）。它是**一段导语 + 三条起步动作 + 一份全站目录**，
不承载学习计划正文。计划与题库各自独立成页，放在 `reference/` 下：

> **「从哪开始」是动作清单，不是卡片网格**（v2 改的）。它原来 5 张卡里有 4 张只是「点到另一个
> 已经在侧栏和完整目录里的地方」，和最下面的完整目录抢同一份活，于是读者读完仍然不知道
> 「我现在该做什么」——而这是全站唯一没人回答的问题（侧栏答「有哪些页」，完整目录答
> 「68 页在哪」，计划 §6 答「整条路线长什么样」）。
> 现在三条动作，动词开头，说清做什么 / 花多久 / 做完得到什么，链接只作为每一步的手段内嵌在句中。
> **写这一节时不要退回成卡片**：一旦每张卡只是在指路，它就又变回一个小目录。

| 页 | 是什么 | 源文件 |
|---|---|---|
| `reference/plan.html` | 学习计划全文（§0–§7 + 附） | `plan/roadmap.md` |
| `reference/questions.html` | 242 题题库（按域分组 + 练习打勾） | `plan/questions.md` |

两份 `.md` 是源文件，**不出现在任何导航里**，只在维护说明中提及。`plan/` 目录下只有 `spec.html` 还保留一份渲染版（开发文档，不属于站点页面）。

**侧栏这几个固定入口**（相对路径按材料页 / 目录页所在的层级写）：

| 段 | 是什么 | 去哪 | href |
|---|---|---|---|
| 往上 | `← 总目录` | 入口页 | `../index.html` |
| 这一层 | 步骤名（**材料页上是链接**） | 该步骤的材料目录 | `index.html` |

| 参考 | `题目索引` | 题库页 | `../reference/questions.html` |

「参考」段有两条，**两页一起构成那一层**，所以这一段的 href 只在 `_dev/pagekind.js` 的 `NAV` 里写一次，`apply-nav.js` 生成、`navcheck.js` 校验都读它，不许各写一份字面量。表里的 `../reference/…` 是**材料页视角**的写法，别处（入口页、参考页自己、`plan/spec.html`）由 `hrefFrom` 现算。

`index.html` / `reference/plan.html` / `reference/questions.html` 三个全站级页面层级不同，侧栏各自成立：

- **入口页**自己是根，`往上` / `这一层` 都不适用，它用 `本页` / `参考` / `学习步骤` / `不占步骤的专题` 四组。
- **参考页**（`reference/plan.html` / `reference/questions.html`）只有 `往上 / 这一层` **两段**，没有 `参考` 段——它们俩本身就是「这一层」，再在第三段里把同一批链接列一遍，就是同一组链接出现两次。
  > 这是「三段」唯一的例外，**有意为之，别去补第三段**。历史上被补过一次：第 2 节的「计划」原文写的是
  > 「侧栏『参考』段从 1 条变 2 条，**68 页统一**」——那句统一的是**参考段的内容**（哪两条链接），
  > 不是分区个数，两条参考页自己反而是没有参考段的那两页。`navcheck` 的 R3 专门守着这条（参考页出现
  > 「参考」段就报错），补之前先读这一段。
- 参考页的 `往上` 就是 `← 总目录`（`../index.html`），和材料页同形；`navcheck` 的 R7 因此不再对参考页分叉。

材料页**底部**再加「上一篇 / 下一篇」，支持顺序阅读。

## 二、每页的固定骨架

> **适用范围**：这一节适用于**材料页**。**目录页（index.html）不套这个骨架**——它需要的是：
> 导语 → 完成标志 → **「与学习计划的对照」表** → 建议先读导读 → 各域的卡片列表 → 怎么用/完成标志，
> 不需要主图、图例、回忆卡。

**目录页的对照表是硬要求**（7 个目录页一个都不能少）：四列 `# / 材料 / 在学习计划里的位置 / 对应题号`，
材料那一列按域分组（用 `rowspan`），00 导读页单独一行（"不覆盖题目"）。

- 表的行数必须和页面上的卡片数对得上：**每张卡片都要在表里出现，表里不许有卡片以外的东西**
  （00 导读做成提示条而不是卡片的页，表里额外给它一行）
- 表格数据不要手写。用 `node _dev/add-crosswalk.js` 从页面自身推导（步骤名取自 crumb、
  域和题量取自各域 `<h2>`、材料与题号取自卡片），推导时会校验
  「各域题量之和 = 总题量」和「卡片里的题号个数 = 该域题量」，对不上就不写文件
- `node _dev/speccheck.js` 会回归这一条

顺序固定，缺一项就不算完成：

| # | 板块 | 组件 | 要求 |
|---|---|---|---|
| 1 | 顶栏 | `.topbar` | **只报位置、不放链接**：`步骤 X · 第 N/M 份 ｜ 域`，见第一节的「导航约定」 |
| 2 | 标题与导语 | `h1` + `.lead` | 导语一句话说清**这一页解决什么问题** |
| 3 | 覆盖题号 | `.qbadges` | 列出这页覆盖的原题号 |
| 4 | 读之前提示 | `.warn` | 指向 `00-先认识这几个词.html` |
| 5 | 三层阅读法 | `.howto` | 第一遍只看图和加粗句 → 第二遍读解释 → 第三遍做回忆卡 |
| 6 | **主图** | `.hero` | 一张心智模型图，全页文字都在解释它 |
| 7 | 正文各节 | `.group-head` / `h2` | 见第三节的写作规范 |
| 8 | 讲解骨架 | `.skeleton` | 3 分钟口述版，**放在正文之后**（看懂再背） |
| 9 | 骨架用法 | `.skelnote` | 紧跟在骨架标题之后的一句话：这一节就是答案怎么用 + `X`/`XX`/`X%` 是留给你填的槽位 |
| 10 | 追问预警 | `details.ask` | 折叠，让人先自己想 |
| 11 | **回忆卡** | `.recall` | 1~2 张，页尾；先自己讲，再展开对照 |
| 12 | 翻页 | `.pager` | 上一份 / 下一份 |

**这张表是「缺一项就不算完成」的硬清单，有 12 项。** 页内目录（正文 `.toc`）不在表里，
因为它是有条件的：章节不足 3 个的页、目录页、入口页都没有。
它的位置在 `h1`/`.lead` 之后、第一个 `<h2>` 之前，由 `node _dev/add-toc.js` 生成——
**不要手写**，加删章节之后重跑一次。

> **第 9 项为什么必须连位置一起管。** 第 8 项只证明「有骨架这一节」，不证明读者知道它是干什么的。
> 读者点进材料页是来找**答案**的，而骨架这一节其实就是答案——不写这一句，读者会以为这一页只有讲解。
> 所以 `speccheck.js` 的判据是 `<h2>…讲解骨架|参考回答…</h2>` **紧跟** `<p class="skelnote">`，
> 不是「页面上有 `.skelnote` 就行」。`09-review-and-answers` 没有骨架节，它的答案在
> 「4. 完整参考回答（3 份）」下面，所以那个标题也认。

**第 7 项（正文各节）还带一条写法约定：这一节答的题号写在 h2 标题末尾。**
`<h2 id="s1">1. 用户量怎么答（<code>ML-11</code>）</h2>` —— 全角括号、顿号分隔、
每个题号包 `<code>`。它是**题号链接落点**的唯一真值（见第一节「题号落点」），
所以不是在标题里加装饰，是在声明「这一节就是这道题的答案」。
写的时候对着该页 `.qbadges` 逐题过一遍：每一题要么在某个标题里出现，
要么确实整页才是它的答案（那就不写，走兜底）。**别写别页的题号**——
`buildLandings()` 会拿 `.qbadges` 比对后报错。

### 数字槽位：`X` / `XX` / `X%`

材料里凡是**要填你自己项目数字**的地方，写的都是占位符：

```
知识库目前 XX 万段，单次问答检索加精排的 P95 是 X 秒；加了混合检索之后，
专有名词类问题的命中率从 X% 提到 Y%。
```

**这不是没写完，是刻意的槽位。** 别人项目的数字填进去就是假的，而且这几个数正是分差所在——
讲得出来自证，讲不出来当场露馅。所以：

- 槽位一律写成 `X` / `XX` / `XXX` / `Y` / `X%`，**不要编一个具体数字充数**；
- 用 `<span class="blank">X</span>` 包起来，由 `style.css` 画成虚线底的填空样式——
  「留白」要看得出来是留白，否则公开版里读起来就是「作者没写完」；
- 每一节 `.skelnote` 里有一句说明它是什么（见上一条）；
- **只在「要你填数字」的地方包**。判据有两条，缺一不可：

  | 场景 | 判据 | 例 |
  |---|---|---|
  | 带 `【数字】`/`【用户量】`/`【降本数字】` 标号的段落 | 段落里的 `X` / `Y` 都是槽位 | `【数字】知识库目前 XX 万段…` |
  | 正文里的引语（「回答示例：…」） | `X` / `Y` **后面紧跟量词**（万 / 秒 / 毫秒 / 元 / GB / % / 天…） | `我们大概 XX 万份文档` |

- **反例（不要包）**：
  - 修辞占位——「假设让你做一个 `XX` 系统」「你对 `XX` 了解到什么程度」「你是想问 `X` 还是 `Y`」。
    这里的 `XX` 是「某个具体的东西」，不是数字，包上就变成另一个意思了；量词判据正好把它们滤掉。
  - UI 文案模板——「数据更新于 `X` 分钟前」。这个 `X` 是**程序运行时填的**，
    不是「换成你自己项目的数据」，包成填空槽位会指错方向。
  - `<pre>` / `<svg>` 里面。SVG 里 `<span>` 不是合法子元素，会把图弄坏。

> 批量包那一次跑的是 `_dev/oneoff/add-skelnote.js`（`【数字】` 段落）和
> `_dev/oneoff/blank-inline.js`（正文引语）。之后新写的槽位**手写 `class="blank"`**，
> 没有生成脚本——`speccheck.js` 管不到这件事（它没法判断一个 `X` 该不该包）。

## 三、写作规范（内容）

### 1. 场景优先，结论在后

每一节开口先给**具体场景**，再给结论。

> ❌ 「路径模型现场决定」 vs 「路径人写死」
> ✅ 「客户发来一封邮件，把里面的订单信息存进表格。」→ 两种做法 → 三个判断问题

### 2. 术语即时拆

- 概念词第一次出现时用「」标出并**当场用大白话解释**
- 能换成日常说法就不写缩写：写"承诺的响应时间"，不写 SLA
- 前置页 `00` 已经解释过的词，可以放心直接用，但页首要有指向 `00` 的提示

### 3. 每个抽象描述必须配例子或反例

表格里的"原则"类条目要**单独一列放反例**。

### 4. 密度控制

- **一屏一个新概念**，不要一屏五个
- 并列条目超过 4 条时，拆成"**最常用的 N 条讲透（带反例）+ 其余列出来**"
- 单页可见文字（去掉标签和 SVG）控制在 **4000~6000 字符**（±10% 可接受）；超了说明该拆页或该砍
- **例外**：前置页 `00` 和自查页 `09` 属于**查阅型页面**（术语表、题库），不受字数上限约束

### 5. 讲"为什么"，不只讲"是什么"

读者没有实战经历，所以：**先讲没有它会怎样，再讲它怎么解决**。

### 6. 讲解骨架不改通俗

它是给"已经看懂、要背话术"的阶段用的，保持紧凑，不要加类比。

---

### 7. 步骤 2 的材料多一节「动手清单」

步骤 2（做系统）的知识必须在项目里落地，所以每份材料末尾用 .handson 组件列一节「这些知识怎么在你项目里验证」。要求写**可执行的动作**，不是「理解 XX」。

## 四、图示规范

### 1. 四种图型，各对应一类知识

| 图型 | 组件 | 用在什么知识上 |
|---|---|---|
| 主图（SVG） | `.hero` + `.svgfig` | 一页一个心智模型：循环、分层、全景 |
| 流式管道 | `.pipeline` | **过程**：步骤序列，节点可折叠看解释 |
| 内联 SVG | `.svgfig` | **对比 / 结构**：并排比较、层次关系 |
| 比例条 | `.dilute` | **反例 / 数量关系**：占比、增长、稀释 |
| 决策树 | `.tree` | **判断标准**：何时拆、怎么排查 |
| 追问链 | `.qchain` | **层层递进**：一个主问题套一串追问 |

`.qchain` 用带轨道的编号列表表示"一问套一问"的线性序列（比如计划第 4 节的高频追问链）。
它替代了早期用 `└─` 画的字符树——**那些其实每个节点只有一个追问，是链不是树**，
所以用编号链比嵌套树更贴切，窄屏也不会横滚。

内部结构是 `<li><span class="ask"><span class="lbl">主问题</span>问题</span><span class="hint"><span class="lbl">要点</span>要点</span></li>`。
`.lbl`（主问题 / 追问 / 要点）是**写在字面上的角色标签**，不是装饰——这组组件曾经只在
第一条的序号上涂了 `--c-model` 色而全页没有图例，读者只能猜那个颜色是「最重要」「已完成」
还是「当前项」，正是第四节那条铁律的反例。**用文字说清角色，比给一个颜色便宜也更准。**

`.ask` 这个类名**不能改成 `.q`**：`.q` 是全站的题号徽章（`.qbadges` 和目录页对照表在用），
撞上去会让每条追问被套上徽章的底色和圆角，见第六节。

**「要点」不是名词清单，是一句「按什么顺序、讲哪几件事」的话。** 这条口径是必须的，
因为 `.qchain` 的读者是拿着它练口述的人：`要点：索引类型 / 向量量化 / 缓存 / 并行召回`
这样的名词串只能用来打勾，起不了头；要写成"照着它就能开口"的样子。

- 要点是**对应材料页里那套答法的压缩版**，不是新编的清单——写之前先读那一页的 `.skeleton`；
- **每一条都要有要点**（主问题和追问一样），空着等于告诉读者"这题不用准备"；
- 要点只讲**顺序和该讲哪几件事**，**不编具体数字**——数字留在材料页的 `【数字】` 槽位里，
  由读者填自己的（见第二节「数字槽位」）。编出来的数字是假的具体，比没有更坏；
- 收尾那句通常是"一句话原则"或者"上位的判断标准"，它才是分差所在。

> 页面上没有例子可抄时**不要凭类名猜结构**：`.qchain` 目前只在 `plan/roadmap.md` 里用，
> 而它是 md，渲染前看不到效果——写完必须真的渲染一次看一眼。

### 2. 颜色编码"对象类型"，且**必须给图例**

| 颜色 | 含义 |
|---|---|
| 紫 `--c-user` | 用户 |
| 蓝 `--c-model` | 模型 / 决策 |
| 橙 `--c-tool` | 工具 / 执行 |
| 绿 `--c-store` | 产出 / 存储 |
| 灰 `--c-data` | 数据 / 状态 |
| 红 `--c-risk` | 风险 / 限制 |

> **铁律：只要用了颜色区分语义，就必须在同页给出 `.legend` 图例。**
> 没有图例的颜色编码等于制造困惑——这是我们踩过的坑。

这六个色值**不要写死在 SVG 里**，用 `var(--c-*)`。它们跟站点变量一样有深色版：
浅色定义在 `:root`，深色分两处映射到 `--dk-c-*`（跟随系统 / 手动切换），
漏一处就会出现「图里某一类盒子在深色下掉回浅色底」——`node _dev/themecheck.js` 回归这一条。

### 3. 禁止事项

- **禁止**把 ASCII 图放进 `<pre><code>`（箭头是字符、不能缩放、颜色不承载信息）。
  过程用 `.pipeline`、结构用 `.svgfig`、层层递进用 `.qchain`。
- **禁止**写死像素宽度、禁止绝对定位叠层
- SVG 一律用 `viewBox` 自适应；**谨慎使用 `transform="rotate()"`**，会绕过常规间距判断，用前先算好间距
- 每张图下面必须有**一句话说明这张图在讲什么**，措辞统一用「**这张图在说什么**」

> 这三条都有脚本兜底：`node _dev/speccheck.js` 会检查图例、图说措辞、以及代码块里有没有残留的字符画。

## 五、自检清单

### 1. 结构自检（脚本，必过）

```bash
node _dev/checklinks.js      # 死链 + 锚点 + 标签配对 + 正文文件名 + 敏感词
node _dev/speccheck.js       # 图例 + 图说措辞 + ASCII 图 + 目录页对照表 + 12 项骨架
node _dev/density.js         # 每页可见字符数是否落在 3600~6600 区间
node _dev/navcheck.js        # 七条导航规则
node _dev/themecheck.js      # 深色配色的两对映射块（跟随系统 / 手动切换）逐项对齐
node _dev/rendercheck.js     # 68 页 × 1440/768/360 三档视口的溢出与栅格（慢，要起无头浏览器）
```

上面六个是**校验**。还有七个**生成**脚本，都支持 `--check`：只比对、只报告漂移、不改文件，
有漂移就退出码 1。**改完内容之后按依赖顺序跑一遍，否则 `--check` 会报漂移**：

```bash
node _dev/build-plan.js --check      # reference/plan.html 的计划正文 ≡ plan/roadmap.md
node _dev/build-questions.js --check # reference/questions.html 的 242 题 ≡ plan/questions.md + 各页徽章
node _dev/add-crosswalk.js --check   # 7 个目录页的「与学习计划的对照」表
node _dev/apply-nav.js --check       # 导航外壳（topbar + 三段侧栏 + 配色引导/跳到正文/app.js）
node _dev/add-toc.js --check         # 材料页正文开头的「本页目录」
node _dev/link-questions.js --check  # 三个消费页的题号链接（399 处，带页内锚点）
node _dev/build-search.js --check    # assets/search-index.js
```

顺序：改了 `plan/roadmap.md` 就跑 `build-plan.js`（它内部会调 `linkify()`，题号链接不会丢）；
改了 `plan/questions.md` 就跑 `build-questions.js`；改了任何一页正文就跑 `add-toc.js` + `build-search.js`；
新增一页还要先跑 `apply-nav.js`。

> 删/加计划里的一节会让其后**所有锚点整体前移**（`md.js` 的编号是跨层级全局计数器），
> 消费锚点的是 `reference/plan.html` 自己的 `.toc` 和 `assets/search-index.js`，两个都能自动再生，
> 跑一遍上面两个脚本就好。**`.toc` 过期时 `checklinks.js` 会报「锚点不存在」——它就是重编号的金丝雀。**

> 改**材料页的 h2 标题**（包括只往末尾追加题号）同理牵动两处派生物：`add-toc.js` 的页内目录
> 和 `build-search.js` 的章节名，改完按 `add-toc` → `build-search` 的顺序补跑。
> 落点锚点本身不用手动维护——它由 `link-questions.js` 从标题现算，跑一遍就同步了。

这些脚本都在仓库根目录下执行，任一不过就退出码 1。

`checklinks.js` 检查五项：

- **死链**：所有 `.html`/`.md` 里的相对链接，目标文件是否存在
- **锚点**：`xxx.html#sec-2` 里的 `#sec-2` 在目标页是否存在
- **标签配对**：`div`、`details`、`table`、`svg`、`rect`、`text`、`ul`、`nav` 等开闭数量是否一致
- **正文文件名**：正文里以纯文本提到的文件名必须真实存在（改文件名时最容易漏的一类）。
  这一项的输出**带扫描计数**，且必须带。

> 为什么计数是这一项的一部分：它的校验点**几乎全部**来自学习计划 §8「配套学习资料」
> 那张材料表里的 `<code>文件名</code>`。那一节一旦缩水，计数就跟着掉，
> 检查范围缩到零，和真的零问题长得一模一样。**不打印计数就是静默失效。**
>
> 也**不给它设数字下限**：它的校验力本来就弱（只看裸文件名，不看路径），
> 同一个问题由第 ① 项死链检查覆盖，而且更强（连路径一起验）。
> 设一个「至少 N 处」的下限只会逼着人保留冗余内容去喂检查器。
- **敏感词**：材料要在工作场景下看，正文里不能出现明显的非工作场景字眼

`speccheck.js` 检查四件事：用了 SVG 就必须有 `.legend`；每张图下要有「这张图在说什么」；
代码块里不能有字符画（判据：≥2 行且含框线字符或多行流程箭头——单行箭头和公式不算）；
目录页必须有且只有一张「与学习计划的对照」表，且表行数与卡片数一一对应。

`navcheck.js` 检查七条导航规则（顶栏无链接 / 无自链接 / 三段齐 / 当前页标记唯一 /
材料页「往上」两条齐 / 目录页「往上」只一条 / 每页都能走回入口页）。

`speccheck.js` 还检查**材料页的 12 项骨架是否齐备**（见第二节那张表）。

> 豁免有**两条**，别当成一条（判据都在 `_dev/pagekind.js`，脚本里一律不要再手写正则）：
>
> | | 谁豁免 | 依据 |
> |---|---|---|
> | 字数区间（`density.js`） | 入口页 / 目录页 / 参考页 / `00-*` / 自查页 | 本节 `00` 和 `09` 那条例外 |
> | 12 项骨架（`speccheck.js`） | 入口页 / 目录页 / 参考页 / `00-*` | 本段 |
>
> **自查页不豁免骨架。** 规范原文写的是它可以简写，但它现在 12 项一项不少；
> 要求它不会误伤，少一层检查才是真的损失。
>
> 这两条此前被写成同一个正则、且两边口径其实不同，是两个真存在过的 bug：
>
> 1. `density.js` 的豁免正则没有前缀锚定（`/(index|00-key-terms|…)\.html$/`），于是
>    `step-1-foundation/03-vector-store-and-index.html` 的 `-index.html` 尾巴命中了
>    `index\.html$`，**那一页被静默豁免至今**。实测 3826 字，一直在区间内，所以没显形。
> 2. `speccheck.js` 的正则有前缀锚定（`(^|\/)(…|review-and-answers)\.html$/`），
>    而 `step-1-foundation/09-review-and-answers.html` 前面是 `09-` 不是 `/`，
>    **于是它反而一直在被要求套满 12 项**。那一页恰好 12 项都齐，所以也没显形。
>
> 教训：**「口径一致」的注释不会让口径一致**。判据只留一份，注释里说的才可能成立。

> 这条规则是有来由的：`step-3-frontend-and-cost/07-browser-compat.html` 和
> `10-usage-and-cost.html` 曾经漏掉了「追问预警」这一项，而当时没有任何检查盯着它——
> 全靠临时写脚本扫才发现。补上规则之后，同一类漏项会在自检里直接暴露。

### 2. 布局自检（探针，必过）

## 六、已知的坑（都是实际踩过的）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 管道用 `flex-basis` + 允许换行 | 最后一个节点被挤到第二行还拉满宽度，尾箭头悬空 | `flex: 1 1 0` 均分 + `flex-wrap: nowrap`；窄屏整体转竖排 |
| 颜色编码没给图例 | 读者问"这两种颜色是什么意思" | 用了颜色就必须给 `.legend` |
| 用颜色标注「哪个是重点」而不用文字 | 追问链里只把第一条的序号涂成蓝色，读者问「为什么 1 有颜色、后面的 2345 没有」——颜色只能表达「不同」，表达不了「不同在哪」，没有图例时连「不同」都读不出来 | **角色写在字面上**（`.lbl` 的「主问题 / 追问 / 要点」），颜色只做同一层内的并列区分 |
| 标签内嵌在段落开头 | 标签被正文"吃"掉，段落感消失，整页看着乱 | 用 `<dl>` + grid 两栏，标签左列对齐 |
| 概念块用卡片边框 | 20 个盒子叠起来线条噪音大 | 改用一条底部分隔线，结构靠对齐和留白 |
| 用 `:last-child` 给「右侧标签」让位（`margin-left:auto`） | 大多数条目只有一个文字 span，它正好是 last-child，被整段推到右边，侧栏全歪 | **布局关键样式必须挂显式 class**（如 `.meta`），不要靠结构位置猜 |
| 窄屏栅格写 `grid-template-columns: 1fr` | `1fr` 的隐式最小值是 auto（内容宽度），宽表格的 min-content 会把整页撑破 | 写 `minmax(0, 1fr)`，并给宽表格加 `overflow-x:auto` |
| 比例条用固定文字宽度 | 两行一样宽，看不出占比差异 | 条形总宽固定，彩色段宽度 = 真实占比 |
| 旋转文字贴边 | 和箭头只有 1px 间距 | 提前算好间距，留 8px 以上 |
| 用 md 而不是 HTML | 排版、折叠、图示都表达不了 | 材料统一用 HTML + 共用 `assets/style.css` |
| 同一组导航在 topbar 和侧栏各写一遍 | 58 个材料页上两处一字不差，读者要在两个地方找同一条链接，交互分散 | **导航只有一个面：全在侧栏**；topbar 只报位置，里面不许有 `<a>` |
| 同一个页面在侧栏出现两次 | 「← 材料目录」和紧跟其后的「步骤 2 · 做系统」指的是同一页，一条是链接一条是标题，看着重复 | **步骤名本身就是回材料目录的入口**（材料页做成链接、目录页留纯文本），不再单放一条 |
| 侧栏出现指向当前页的链接 | 目录页上那一步指向它自己，点了没反应 | 当前页不用链接表达——正文大标题就是标记；材料页用 `.item.cur`，且只有一条 |
| 目录页的对照表只做了一个 | 步骤 1 有「与学习计划的对照」，其余 6 个目录页没有，读者按题号反查时有的页能查、有的页不能 | 7 个目录页都要有，且行数与卡片数一一对应；`_dev/speccheck.js` 回归 |
| 生成脚本不可重入 | `add-crosswalk.js --check` 永远报「已经有对照表了，先删掉再加」，这个检查等于没有 | **`--check` 必须是真比对**：算出期望结果、和文件比、只报差异；脚本要先能拆掉自己的产物再装回去 |
| 同一个类名两种东西共用（CSS 侧） | `.qchain` 里的问题写成了 `<span class="q">`，而 `.q` 早就是题号徽章。`.qchain .q` 只声明了 `display` 和 `font-weight`，**没写的照样从 `.q` 继承**——`background` / `border-radius` / `padding` / `font-family` / `font-size` 全漏进来，每条追问被画成一条满宽的灰色药丸、还是等宽小字，看着像标签不像问题。同一类问题还有一处：入口页的完整目录用了 `.tree`，而共用表里的 `.tree` 是决策树（靠页内 `<style>` 优先级高才没串味） | **新组件的内部类名先全站搜一遍**；两个东西共用一个名字时，特异性只救你写出来的那几条。入口页的目录已改名 `.sitemap`。改完 `.qchain` 要真的渲染一次看，全部检查器都测不出「穿错了衣服」 |
| 用类名当数据源 | `.q` 这个类在材料页装题号、在目录页装「H 域 18 题」，按类名抓题号会多算出 13 个不存在的题号，还会灌进搜索索引 | **抓数据要连形状一起校验**（`/^[A-Za-z]+-\d+$/`），别只认类名 |
| 生成器重建整段 HTML 时丢了派生链接 | `build-plan.js` 从 `roadmap.md` 重建计划正文，一次重建就把 399 条题号链接里的 160 条抹掉了 | 派生步骤要串在生成管线里（`build-plan` 内部调 `linkify()`），不能是「跑完 A 再手工跑 B」 |
| 约束靠「某一页恰好含全集」侥幸成立 | `link-questions` 原先查「**目标页里出现的**题号」，而入口页恰好含 242 题的全部，约束是**间接**守住的；计划正文一搬走，检查范围静默缩小，脚本照旧打印「✓ 每个题号恰好一份材料认领」 | 改成**比两个集合**（全站引用集 ≡ 材料认领集），不看任何字面量、不依赖哪一页含全集 |
| 一条不变量分属两个脚本、各写一份判据 | 题号的正则与 crumb 解析在 `link-questions` 和 `add-crosswalk` 各写了一遍，于是**三条本该闭合的边只连上两条**（Σ各目录页题量 ≠ 认领总数 没人查） | 抽 `_dev/qids.js` 单源，并补上缺的那条跨页的边 |
| 给列表条目自动编号，而条目文字里已经有编号 | `.toc` 是 `<ol>`、条目又是标题原文（「0. 先看一个场景」），60 个页面上每行都印成「1. 0. 先看一个场景」 | 目录条目照抄标题原文，序号交给标题自己；`.toc ol` 关掉 `list-style` |
| 顶栏加控件把它撑高一格 | `--topbar-h` 是锚点落点的唯一依据，按钮 padding 稍大就 51→56px，带 `#锚点` 打开时目标被盖住 | 加控件先量高度；`app.js` 在运行时把实测高度写回 `--topbar-h`，CSS 里的静态值只给无 JS 兜底 |
| 两行长得一样、一个能点一个不能点 | 宽屏侧栏里「步骤名」和它下面第一份材料都是一行 `--fg` 文字，可前者在目录页上是死的、在材料页上是活的，只有 `:hover` 才分得出 | **可点性要写在静止状态里**：`--fg` 能点、灰色是标签；可点的补 `←`，和 `← 总目录` 同一套语言 |
| 检查器照字面写，反而逼内容迁就它 | 落点不变量原写成「一个题号不许出现在两个 h2 标题里」，磁盘上立刻撞到反例：`YC-5` 题干是「技术架构：你怎么拆模块？数据怎么流转？技术选型怎么做？」，两节各答一部分、两节都该写它。硬套会把作者逼成**少声明一处「这节也答了这题」**——为了检查器好看而少给读者信息 | 复合题允许写多处，**落点取文档顺序里第一个**（确定性的，且第一个必定是「往下读就有答案」的那节）。新不变量先在磁盘上跑一遍，撞到反例先问「是数据错了还是规则错了」 |
| 一个生成物有两个消费者，其中一个不校验 | 题号落点的锚点加在**跨页**链接上（`../step-1-foundation/…html#s5`），`checklinks.js` 会验锚点存在；但同一页里纯页内的 `href="#s3"` 被 `checklinks.js:58` 一句 `continue` 放过了。**同一件事两条路，只有一条有网** | 往页面里加锚点前先确认它走的是**被校验**的那条路；纯页内锚点目前无网，别指望检查器 |

## 七、新增一页的步骤

1. 确认它覆盖哪个主题、哪些题号、属于哪个步骤
2. 复制骨架（顶栏 → 导语 → 题号 → 读之前 → 阅读法 → 主图 → 正文 → 骨架 → 追问 → 回忆卡 → 翻页）
3. 先画**主图**，再围绕图写文字——图是主干，文字只负责把图讲通
4. 写正文时对照第三节的写作规范，尤其是"场景优先"和"术语即时拆"
5. 把新页登记到 `index.html` 的卡片列表和「与学习计划的对照表」里
6. 跑生成脚本：`apply-nav.js`（装外壳）→ `add-toc.js`（生成本页目录）→ `build-search.js`（重编索引）
7. 跑第五节的全部自检；**导航、页内目录、搜索索引都不要手写，跑脚本生成**

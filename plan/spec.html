学习资料规范

规定学习材料怎么写、怎么排版、怎么自检。新增或修改任何一页材料前先看它。

关于这一页

这是 plan/spec.md 的渲染版本，方便在浏览器里读。要改内容请改 Markdown 源文件后重新生成，这一页是生成出来的。

这份文档规定学习材料怎么写、怎么排版、怎么自检。新增或修改任何一页材料前先看它。

目标读者定位：接触过 AI、但很多概念不懂、没自己写过。

├── assets/

│   ├── index.html               ← 该步骤的材料目录
│   ├── 00-key-terms.html        ← 前置页，不属于任何域
│   └── 01~09-*.html             ← 正式材料
├── step-2-systems/              ← 步骤 2

根目录只放 index.html、README.md、.gitignore，其余一律进子目录。

  • 编号 NN-topic.html（英文小写连字符），数字即阅读顺序；页面标题和正文仍用中文
  • 子目录名、文件名一律英文，避免 URL 出现 %E4%BB%80%E4%B9%88 这类编码
  • _ 前缀 = 开发/辅助文件，统一收在 _dev/，不进入目录页的卡片列表
  • 每份材料只覆盖一个知识主题，且必须能对应到学习计划里的域和题号

导航约定（全站统一外壳）

核心原则：目录必须常驻可见，不能靠滚回去找。 所有页面共用一套导航外壳：

┌─ 顶栏（sticky）─────────────────────────┐
│ ← 总目录   学习计划全文    步骤 X · 第 N/M 份 │
├──────────┬──────────────────────────────┤
│ 侧栏目录  │  正文                         │
│（sticky） │                              │
│ · 上层出口 │                              │
│ · 兄弟页面 │                              │
│ · 当前高亮 │                              │
└──────────┴──────────────────────────────┘

三层结构（像屏幕栈一样，每层都有明确的返回）：

层级页面侧栏内容
1 · 着陆页index.html全站目录（两个步骤的全部材料 + 附录）
2 · 步骤目录step-N-xxx/index.html该步骤的材料列表
3 · 材料页step-N-xxx/NN-topic.html该步骤的材料列表 + 当前页高亮

实现要求：

  • 布局用 .layout（grid 两栏）+ .sidenav（sticky），不要用绝对定位
  • 窄屏（≤980px）自动降级：侧栏变成可换行的 chip 列表，不再是侧边栏
  • 窄屏下栅格列必须写 minmax(0, 1fr)，写 1fr 会被宽表格的 min-content 撑破
  • 宽表格在窄屏改为横向滚动（display: block; overflow-x: auto），不要撑宽整页
  • 所有链接和折叠标题要能用键盘 Tab 到达，且有可见的焦点样式（:focus-visible）

入口唯一：全站只有一个着陆页（index.html），它同时也是学习计划全文的所在页。计划的 .md 是源文件，不出现在任何导航里，只在维护说明中提及。

顶栏的三个固定入口：

按钮去哪相对路径（材料页所在层级）
← 总目录入口页顶部../index.html
材料目录该步骤的材料目录index.html
学习计划全文入口页内的计划章节../index.html#plan

材料页底部再加「上一篇 / 下一篇」，支持顺序阅读。

换目录结构时：先改这一节，再全量跑一次链接检查 + 跨屏验证（至少 1440 / 768 / 360 三档）。

二、每页的固定骨架

适用范围：这一节适用于材料页。目录页（index.html）不套这个骨架——它只需要：顶栏导航 + 导语 + 卡片/表格列表 + 状态说明，不需要主图、图例、回忆卡。

三、写作规范（内容）

1. 场景优先，结论在后

每一节开口先给具体场景，再给结论。

❌ 「路径模型现场决定」 vs 「路径人写死」

✅ 「客户发来一封邮件，把里面的订单信息存进表格。」→ 两种做法 → 三个判断问题

2. 术语即时拆

  • 概念词第一次出现时用「」标出并当场用大白话解释
  • 能换成日常说法就不写缩写：写"承诺的响应时间"，不写 SLA
  • 前置页 00 已经解释过的词，可以放心直接用，但页首要有指向 00 的提示

3. 每个抽象描述必须配例子或反例

表格里的"原则"类条目要单独一列放反例。

4. 密度控制

  • 一屏一个新概念，不要一屏五个
  • 并列条目超过 4 条时，拆成"最常用的 N 条讲透（带反例）+ 其余列出来"
  • 单页可见文字（去掉标签和 SVG）控制在 4000~6000 字符（±10% 可接受）；超了说明该拆页或该砍
  • 例外：前置页 00 和自查页 09 属于查阅型页面（术语表、题库），不受字数上限约束

5. 讲"为什么"，不只讲"是什么"

读者没有实战经历，所以：先讲没有它会怎样，再讲它怎么解决。

6. 讲解骨架不改通俗

它是给"已经看懂、要背话术"的阶段用的，保持紧凑，不要加类比。

7. 步骤 2 的材料多一节「动手清单」

步骤 2（做系统）的知识必须在项目里落地，所以每份材料末尾用 .handson 组件列一节「这些知识怎么在你项目里验证」。要求写可执行的动作，不是「理解 XX」。

四、图示规范

1. 四种图型，各对应一类知识

图型组件用在什么知识上
主图（SVG）.hero + .svgfig一页一个心智模型：循环、分层、全景
流式管道.pipeline过程：步骤序列，节点可折叠看解释
内联 SVG.svgfig对比 / 结构：并排比较、层次关系
比例条.dilute反例 / 数量关系：占比、增长、稀释
决策树.tree判断标准：何时拆、怎么排查

2. 颜色编码"对象类型"，且必须给图例

颜色含义
紫 --c-user用户
蓝 --c-model模型 / 决策
橙 --c-tool工具 / 执行
绿 --c-store产出 / 存储
灰 --c-data数据 / 状态
红 --c-risk风险 / 限制

铁律：只要用了颜色区分语义，就必须在同页给出 .legend 图例。

没有图例的颜色编码等于制造困惑——这是我们踩过的坑。

3. 禁止事项

  • 禁止把 ASCII 图放进 <pre><code>（箭头是字符、不能缩放、颜色不承载信息）
  • 禁止写死像素宽度、禁止绝对定位叠层
  • SVG 一律用 viewBox 自适应；谨慎使用 transform="rotate()"，会绕过常规间距判断，用前先算好间距
  • 每张图下面必须有一句话说明这张图在讲什么

五、自检清单

1. 结构自检（脚本，必过）

node _dev/checklinks.js      # 死链 + 锚点 + 标签配对，仓库根目录下执行

会检查三项，任一不过就退出码 1：

  • 死链：所有 .html/.md 里的相对链接，目标文件是否存在
  • 锚点：xxx.html#sec-2 里的 #sec-2 在目标页是否存在
  • 标签配对：div、details、table、svg、dl、ul、nav 的开闭数量是否一致

2. 布局自检（探针，必过）

我（AI）看不到渲染结果，所以用几何测量代替肉眼：

# 1) 在页面 </main> 后插入 <script src="../_dev/probe.js"></script>   ← 材料页都在一层子目录下
# 2) 无头浏览器打开，读取 ===LAYOUT=== 报告
headless_shell --no-sandbox --in-process-gpu --dump-dom "file://.../_c.html"

探针会报出：流式管道是否换行、页面是否横向溢出、SVG 文字是否越出 viewBox / 宽于所在盒子 / 互相重叠、比例条实际占比。

注意：探针的重叠检测用 getBoundingClientRect（屏幕坐标）才能正确处理 rotate。

3. 人工自检（读者视角，必做）

  • 只看导语，能不能知道这页要讲什么？
  • 随机挑 2 节，按"场景 → 结论"读下来能不能懂？
  • 有没有没解释就出现的术语？
  • 有没有哪一屏堆了 3 个以上新概念？
  • 每张图下面那句话，是不是真的解释了图？

六、已知的坑（都是实际踩过的）

坑现象正确做法
管道用 flex-basis + 允许换行最后一个节点被挤到第二行还拉满宽度，尾箭头悬空flex: 1 1 0 均分 + flex-wrap: nowrap；窄屏整体转竖排
颜色编码没给图例读者问"这两种颜色是什么意思"用了颜色就必须给 .legend
标签内嵌在段落开头标签被正文"吃"掉，段落感消失，整页看着乱用 <dl> + grid 两栏，标签左列对齐
概念块用卡片边框20 个盒子叠起来线条噪音大改用一条底部分隔线，结构靠对齐和留白
用 :last-child 给「右侧标签」让位（margin-left:auto）大多数条目只有一个文字 span，它正好是 last-child，被整段推到右边，侧栏全歪布局关键样式必须挂显式 class（如 .meta），不要靠结构位置猜
窄屏栅格写 grid-template-columns: 1fr1fr 的隐式最小值是 auto（内容宽度），宽表格的 min-content 会把整页撑破写 minmax(0, 1fr)，并给宽表格加 overflow-x:auto
比例条用固定文字宽度两行一样宽，看不出占比差异条形总宽固定，彩色段宽度 = 真实占比
旋转文字贴边和箭头只有 1px 间距提前算好间距，留 8px 以上
用 md 而不是 HTML排版、折叠、图示都表达不了材料统一用 HTML + 共用 assets/style.css

七、新增一页的步骤

  1. 确认它覆盖哪个主题、哪些题号、属于哪个步骤
  2. 复制骨架（顶栏 → 导语 → 题号 → 读之前 → 阅读法 → 主图 → 正文 → 骨架 → 追问 → 回忆卡 → 翻页）
  3. 先画主图，再围绕图写文字——图是主干，文字只负责把图讲通
  4. 写正文时对照第三节的写作规范，尤其是"场景优先"和"术语即时拆"
  5. 跑第五节的三项自检
  6. 把新页登记到 index.html 的卡片列表和「与学习计划的对照表」里

样式样张：同一个内容，四种画法

这一页用同一份内容（RAG 全链路）并列展示几种图示方案，方便你直接对比着挑。 选定之后，我会按这个风格把 9 份材料里的"假图"（ASCII）全部替换掉，并补上设计里列出的那些图。

现状：ASCII 塞进 <pre>

问题所在

01

流式管道：CSS 卡片 + 可折叠说明

推荐用于「过程」

零 JS、响应式、文字自动换行不糊。每个节点可以点开看解释——把"图"和"讲解"合成一个东西，不用来回翻。 节点宽度用 flex:1 1 0 均分，永远不会换行；窄屏（<640px）自动转成竖排。

离线阶段 · 把资料变成能查的知识库

文档
PDF / Word / 网页 / 数据库。这一步的常见坑：扫描件没有文字层，必须先 OCR。
→
解析
提取文字、表格、图片。双栏排版容易被读串行，表格容易拆散。
→
切分
按语义完整性切，不是按字数硬切。太大会稀释语义，太小会丢指代关系。
→
向量化
每段变成向量。换 embedding 模型 = 全库重算，所以这是一次定好的决策。
→
入库
向量库存向量，ES 存原文和元数据。元数据要带来源、页码、生效日期、权限。

在线阶段 · 用户提问 → 回答

提问
口语、短、可能带指代。多轮场景要先做指代消解。
→
查询优化
改写 / 多查询 / 子查询 / HyDE。这是延迟的大头，通常要加缓存。
→
召回
关键词和向量两路并行，各取 Top 50，用 RRF 融合。目标是不漏。
→
精排
交叉编码器把 100 个候选压到 Top 5。语义相似 ≠ 能回答问题。
→
生成
证据 + 引用要求 + 拒答约束一起进 Prompt。要允许它说"不知道"。
02

结构图：内联 SVG

推荐用于「对比 / 结构」

用 viewBox 自适应缩放，文字是真文字（可选中、可搜索、跟着深色模式换色）。 适合画"两种方案并排对比"这种 CSS 很难表达的东西。

03

比例对比：把"稀释"画出来

推荐用于「反例」

讲"chunk 太大会稀释语义"用一段文字很抽象，用比例表示一眼就懂：关键句只占一小块，算出来的向量自然偏。

chunk 太大（800 字）

关键信息「饮料店不提供兔子血」只占 6%，整段向量反映的其实是"园区安全须知"，检索时匹配不准。

chunk 适中（150 字）

同一句话占了 60%，向量能准确表达它，用户问饮料店就能召回这一段。

04

决策树：把判断题画成流程

推荐用于「判断标准」

"什么时候该拆多 Agent"这类问题的答案本质是一串判断。画成树比列成表更容易记住，也更好复述。

① 子任务需要独立的上下文吗？（放一起会互相污染）

是值得拆 —— 这是拆多 Agent 最核心的理由
否继续看 ②

② 子任务之间能并行吗？

是值得拆 —— 拿到并行收益
否继续看 ③

③ 需要不同的工具集 / 权限，或者需要独立评审吗？

是值得拆
否不要拆 —— 拆了只增加通信成本和状态一致性代价，是负收益
05

回忆卡：每页尾部内嵌主动回忆

推荐每页都加

现在自查集中在第 09 份，太晚了。正确做法是每页读完立刻自查——主动回忆比重复阅读有效得多。

合上材料，先自己讲一遍

为什么"语义相似"不等于"能回答问题"？粗排和精排分别用什么技术，为什么？

想完了，展开对照要点

向量检索找的是语义相近的段落，但它们未必能回答用户的具体问题——比如两个段落都在讲差旅，一个是报销标准（用户要的），一个是订票流程（相似的）。双塔把问题和文档分别编码，能预计算所以快；交叉编码把两者拼在一起，注意力能逐词对齐所以准，但每对都要现场推理。

我的建议

图型用在什么知识上说明
流式管道（01）过程：RAG 链路、Agent 循环、PDF 解析主力图型，节点可点开看解释
内联 SVG（02）对比与结构：双塔 vs 交叉编码、HNSW 分层、多 Agent 拓扑精确控制，文字可搜索、适配深色模式
比例对比（03）反例：chunk 稀释、上下文污染、成本构成用视觉比例代替形容词
决策树（04）判断标准：何时拆多 Agent、答不准怎么排查把串行判断画成树，好记好复述
回忆卡（05）每页尾部主动回忆，替代"全部堆到第 09 份"
一个必须说明的限制

我这个会话里的读图工具是坏的（报 cannot get property "fs" without inject），所以我能写出这些图，但没法自己确认渲染效果。

因此设计上我刻意只用了"难以画错"的技术：SVG 全部走 viewBox 自适应、不用绝对定位叠层、不写死像素宽度、文字都放在流式布局里。但最终好不好看、有没有对齐问题，需要你打开这一页看一眼告诉我。
